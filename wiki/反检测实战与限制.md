# 反检测实战与限制

这页是**诚实页**。讲清 sleight 能做什么、做不到什么，以及一个真实的失败案例。

## 分工

| 谁 | 负责 |
|---|---|
| **浏览器内核** | 浏览器**长什么样**：UA、Canvas、WebGL、字体、时区、硬件参数 |
| **sleight** | 浏览器**怎么动**：轨迹、节奏、时序、命中校验 |
| **你的网络** | 出口 IP 的**信誉**：数据中心 vs 住宅、ASN、历史行为 |
| **你的账号/行为** | 访问频率、路径合理性、登录态一致性 |

**三者缺一不可。** sleight 只解决第二条。

## 真实案例：路透社

用本项目实测（不是推测）：

```python
with launch("fingerprint-chromium", fingerprint=42, no_sandbox=True, human=True) as s:
    s.open("https://www.reuters.com/", wait=Load(), timeout=90)
    print(s.title(), len(s.text()))
```

**结果**：
```
title: reuters.com        ← 挑战页，不是真标题
text len: 0               ← 正文 0 字
```

抓文档响应看到真相：

```
HTTP 401  https://www.reuters.com/
HTTP 200  https://geo.captcha-delivery.com/interstitial/?initialCid=...
```

**DataDome 拦截**。关键点：

- **标准 Chromium 被挡。**
- **fingerprint-chromium 也被挡**（同一个种子、开了拟人）。
- 两个都挡 → 卡点**不在指纹**，在**出口 IP 信誉**（数据中心网段）。

**换内核解决不了这个。** 要过这类墙需要住宅代理 / 干净出口 IP，那是网络层的事。

对照组：同一条管线换一个不设墙的站（NPR），立刻拿到 9134 字正文、quality 0.947、
标题作者日期都对。**说明管线是好的，被挡的是网络身份。**

## 什么时候换内核有用

| 症状 | 大概率原因 | 该动什么 |
|---|---|---|
| 首页就 403/401 + 验证码跳转 | IP 信誉 | **换出口 IP**（住宅代理）|
| 能进首页，一交互就被挡 | 行为特征 | 拟人档位调到 `CAREFUL`、放慢节奏 |
| 页面能开但内容被降级/投毒 | 指纹 | 换指纹内核、固定 persona |
| 登录后很快掉线 | 指纹不一致 / 设备绑定 | 固定 `fingerprint` seed + 持久 `profile_dir` |
| 滑块验证码 | 需要真实拖拽 | `s.drag(..., human=CAREFUL)`，见 [[拟人化详解]] |

## 换出口 IP

隧道按 TCP 连接分配地址，而 Chrome 复用 keep-alive socket，所以整轮跑下来会钉在同一个 IP。

**只有新建 `BrowserContext` 能可靠打破**（它自带独立 socket pool）：

```python
with inst.context() as ctx, ctx.session() as s:
    print(ctx.exit_ip())      # 新出口
    s.open(url)
```

**实测无效的做法**：清缓存、加唯一查询串、`emulateNetworkConditions`。

### 硬限制：换出口与用插件互斥

`Target.createBrowserContext` 建的是**无痕**上下文，Chrome 默认不在无痕里启用扩展。
同一个 profile、同一个 URL：`chrome-extension://<id>/…` 在默认 context 打得开，
在新 context 里返回 `ERR_BLOCKED_BY_CLIENT`。

**所以**：如果你的任务依赖插件，就别用 context 换出口——改成**多租几个 profile、
各配各的上游代理**。

## 稳定人格

长期账号任务要的是**一致**而不是**随机**：

```python
with launch("fingerprint-chromium",
            fingerprint=42,                    # 同 seed = 同指纹（实测跨启动一致）
            profile_dir="/data/persona-a",     # 持久 profile：登录态、cookie 都留着
            headless=False) as s:
    ...
```

**反例**：某些内核（如 ungoogled-chromium 的 Bromite canvas 噪声）是**每次会话随机**的——
那在"同一账号 = 同一台设备"的场景里**帮倒忙**。见 [[浏览器内核选择]]。

## sleight 明确不做

- **不承诺绕过任何验证码或风控。**
- **不做指纹伪装**（那是内核的事）。
- **不做代理池 / IP 轮换**（只提供 `context()` 这个换出口的原语和 `exit_ip()` 的验证）。
- **不做调度与队列。**

## headless 的问题

现代 `--headless=new` 与有头差异已小很多，但仍可被检测。做真实任务建议：

```python
launch("fingerprint-chromium", fingerprint=42, headless=False)   # 配 Xvfb/Xvnc
```

但再说一次：多数情况下卡你的**不是** headless，是 IP。
