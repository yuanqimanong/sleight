# 远程部署

这页解决：把 CloakBrowser Manager 部署到一台服务器上，并长期运维它。

**目标机要求**：装了 `docker`（含 compose 插件）和 `sshd`。控制机装 sleight 即可——
部署引擎**只用标准库**，SSH 走系统的 `ssh` 命令。

## 最短路径

```bash
# 1) 记一台主机（顺带建一个 default 部署）
sleight hosts add hk-01 --ssh deploy@10.0.0.12 --dir /srv/cloakbrowser-manager --sudo

# 2) 体检：磁盘、内存、端口占用、docker 版本…
sleight preflight --host hk-01

# 3) 部署（幂等，可反复跑）
sleight deploy --host hk-01

# 4) 看状态
sleight status --host hk-01
sleight token --host hk-01        # 取回 AUTH_TOKEN
```

先看它到底会写什么：

```bash
sleight deploy --host hk-01 --dry-run        # 打印将写入的确切字节
sleight deploy --host hk-01 --dry-run --brief # 不打文件全文
```

## 本机部署

不给 `--ssh` 就是本机（同一条代码路径，只是 runner 不同）：

```bash
sleight hosts add local --dir /srv/cbm
sleight deploy --host local
```

## 关键参数

```bash
sleight deploy --host hk-01 \
  --image <镜像:标签> \        # 不许 latest —— 会被拒绝
  --port 9000 \                # Manager 端口
  --bind 127.0.0.1 \           # 监听地址；要外部访问才改
  --shm-size 2g \              # 浏览器要够大的 /dev/shm，太小会崩
  --template standard          # 规模模板：trial/standard/large/private-net
```

`sleight templates` 打印全部模板、字段说明和推荐值——**每个字段都有一行"填错了会坏什么"**。

## 日常运维

```bash
sleight logs --host hk-01                # 看日志
sleight upgrade --host hk-01             # 换镜像（默认先停机备份）
sleight rollback --host hk-01            # 回上一个镜像
sleight backup --host hk-01              # 停机归档整个 data/
sleight destroy --host hk-01 --yes       # 停并删容器；默认保留 data/
sleight history --host hk-01             # 部署/备份/升级/销毁流水
```

## 从开发机访问

Manager 默认只听回环。开隧道：

```bash
sleight tunnel --host hk-01              # 自动挑本地端口并打印
# 然后本地：
```
```python
from sleight.providers import CloakBrowserManager
mgr = CloakBrowserManager("http://127.0.0.1:19000", token="…")
with mgr.lease() as inst, inst.session(human=True) as s:
    s.open("https://example.com")
```

## 一台机跑多个 Manager

```bash
sleight deployments add hk-01 second --dir /srv/cbm-2 --port 9001
sleight deploy --host hk-01/second
sleight status --host hk-01/second
```
之后所有命令用 `主机/部署名` 定位。**不许在同一个 `/data` 上起第二个 Manager**——会被拒绝。

## 插件下发

```bash
sleight ext push ./plugins/my-ext --host hk-01    # MV3 校验 + 权限检查
sleight ext apply --host hk-01                    # 下发到 profile，然后重启
sleight ext verify --host hk-01                   # 浏览器**真的**加载了吗
sleight ext drift --host hk-01                    # 磁盘与配置是否漂移
```
`verify` 是关键一步——配置写对了不等于浏览器真的加载了。

## 建实例

```bash
sleight profiles create Win-US-02 --preset windows --region us_east \
    --proxy http://user:pass@proxy:8080 --tags us,prod --host hk-01
sleight profiles ls --host hk-01
sleight profiles launch <id> --host hk-01
```
见 [[指纹与人格]]。

## 安全默认

- 部署是**幂等**的，反复跑不会重复建。
- **不可逆动作被拒绝而不是记文档**：不许 `latest` tag、不许 `down -v`、
  不许悄悄轮换正在用的 `AUTH_TOKEN`。
- `destroy` 这类要 `--yes`；非交互环境（CI/管道）里不给就**直接拒绝**，
  不会静默把 `/data` 删掉。
