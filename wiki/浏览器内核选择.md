# 浏览器内核选择

这页解决：sleight 能驱动哪些浏览器、各自什么代价、我该选哪个。

**先摆清分工**：sleight 决定浏览器**怎么动**（轨迹、节奏、时序），浏览器内核决定它**长什么样**
（UA、Canvas、WebGL、字体、时区）。指纹伪装不是 sleight 做的，是内核做的——所以选内核这件事
和选 sleight 是两个独立决策。

## 能驱动的内核

只有一个硬要求：**说 CDP（Chrome DevTools Protocol）**。满足就能驱动。

| 内核 | 开源 | CDP | 稳定人格 | 预编译平台 | 一键装 | 维护风险 |
|---|:--:|:--:|:--:|---|:--:|---|
| 标准 Chromium / Chrome | ✅ BSD | ✅ | ❌ | 全平台 | ❌（系统自带）| 低 |
| **fingerprint-chromium** | ✅ BSD-3 | ✅ | ✅ seed | Win/mac/Linux **仅 x86_64** | ✅ | 中（单维护者、落后上游）|
| CloakBrowser | ❌ 闭源二进制 | ✅ | ✅ seed | Win/mac/Linux | ❌ | 中（商业，最新版要订阅）|
| 其它 Chromium 分支（Brave / Cromite / ungoogled…）| 视项目 | ✅ | ❌ | 视项目 | ❌ | 视项目 |
| **Camoufox / Firefox** | ✅ MPL | ❌ **不支持** | — | — | ❌ | — |

### 标准 Chromium / Chrome —— 基线

```python
launch("chromium")            # 或 "google-chrome"，或绝对路径
```
优点：最可预测、跟上游安全更新最紧、跨平台。
缺点：**没有任何反指纹增强**，`--fingerprint` 这类参数不认。适合开发、调试、内网任务、
以及作为出问题时的回退基线。

### fingerprint-chromium —— 开源方案首选

```bash
sleight browser install fingerprint-chromium
```
```python
launch("fingerprint-chromium", fingerprint=42)
```

- BSD-3 许可，基于 ungoogled-chromium，指纹改动是**C++ 源码级补丁**，不是 JS 注入。
- **保留完整 CDP**，还专门处理了 `Runtime.enable` 泄漏面。
- `--fingerprint=<32位整数>` 派生一整套一致身份：UA/UA-CH、平台、Canvas、WebGL、音频、
  字体、时区、硬件并发数、设备内存。

**实测确认**（本项目在真 binary 上跑过）：同一个 seed 跨启动**指纹完全一致**；换 seed 后
GPU 从 `Intel Iris Xe` 变成 `Intel UHD 620`、核数从 14 变成 28。

**要知道的代价**：
- **仅 x86_64**，没有 ARM 构建（Apple Silicon 上跑不了原生）。
- 落后 Chrome 稳定版约 **3 个大版本**（当前 148，上游 151），且补丁源码延迟约一个月发布。
- **WebGL GPU 元数据伪装只在 Linux 全生效**。
- 作者声明"无技术支持"。

### CloakBrowser —— 闭源但最强

包装器（Python/JS/.NET）是 MIT 开源的，但**真正的浏览器内核是专有闭源二进制**——
补丁源码和构建配置都不公开，无法自建。

- **本地自用免费**：旧大版本（v146）可无 key 直接下载；最新大版本需 GitHub 登录取免费 key
  且限 1 并发；多并发/始终最新要付费订阅。
- **禁止再分发**：不能打包进你的产品、不能做 BaaS 对外提供，那需要单独的 OEM/SaaS 授权。
- 用法：自己从官方渠道下载后传绝对路径给 `launch()` / `LocalLauncher`。

```python
launch("/opt/cloakbrowser/chrome", fingerprint=42)
```

### 明确不支持

- **Firefox 系（含 Camoufox）** —— 它们走 Juggler/Playwright 协议，不是 CDP。sleight 整个
  Transport/Session/事件模型都建在 CDP 上，接它等于再造一套控制栈。
- **WebDriver BiDi** —— 同理，不在范围内。

## 怎么选

```
只是开发/调试/内网         → 标准 Chromium
要开源 + 稳定指纹 + x86_64  → fingerprint-chromium   ← 多数人选这个
要最强隐身、能接受闭源      → CloakBrowser（本地自用）
在 Apple Silicon 上         → 标准 Chromium（fingerprint-chromium 没有 ARM 构建）
要 Firefox                  → 用不了，换别的库
```

**三者对 sleight 是同一套业务代码**，只换初始化参数：

```python
launch("chromium")                                  # 基线
launch("fingerprint-chromium", fingerprint=42)      # 开源指纹
launch("/opt/cloakbrowser/chrome", fingerprint=42)  # 闭源指纹
```
`snapshot()` / `click()` / `extract_document()` 这些一行都不用改。

## 一个重要的期望管理

**换内核解决不了 IP 问题。** 实测：访问 `www.reuters.com`，标准 Chromium 和
fingerprint-chromium **都被挡**（HTTP 401 → DataDome 验证码）。卡点是数据中心 IP 的信誉，
不是指纹。这种情况要配住宅代理，换内核没用。详见 [[反检测实战与限制]]。

## 别自己编译 Chromium

调研结论：Chrome 从 2026-09 起转 2 周一个大版本 + 每周安全更新；全量编译要 100GB 磁盘、
数小时；连有多个维护者的 ungoogled-chromium 在 macOS 端都落后一个大版本。
**用上游预编译产物，别自建。**
