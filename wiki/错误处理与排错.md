# 错误处理与排错

这页解决：报了什么错、能不能重试、怎么定位。

## 异常树

全部继承 `SleightError`，从 `sleight.errors` 或顶层导入：

```python
from sleight import SleightError, ElementError, StaleRef, TimeoutError, LeaseLost
```

| 异常 | 什么时候 | 能重试吗 |
|---|---|---|
| `SleightError` | 所有 sleight 异常的根 | — |
| `AuthError` | CDP 握手被 401/403 拒 | ❌ 先修凭据 |
| `ConnectionError` | 连不上 / 握手失败 / 连接中断 | ✅ 可重连 |
| `TimeoutError` | 等待条件超时（带 `last_value`）| ✅ 视情况 |
| `ProtocolError` | CDP 返回 error / JS 抛异常（带 `code`、`method`）| 视情况 |
| `ElementError` | 选择器没命中 / 零尺寸 / **被遮挡** / 焦点不对 | ✅ 通常重新观察后重试 |
| `StaleRef` | Snapshot Ref 已失效（页面导航过）| ✅ **重新 `snapshot()`** |
| `NotFound` | 实例/资源不存在 | ❌ |
| `NotReady` | 端点没响应（`Plain` 起不了浏览器）| ✅ 自己把浏览器拉起来 |
| `Busy` | 实例被别人租着 | ✅ 等或换一个 |
| `Crashed` | 浏览器进程崩了 | ✅ `recover()` |
| `SessionLost` | 会话没了（tab 被关等）| ✅ 重开 Session |
| `LeaseLost` | **租约丢了，连接被掐断** | ⚠️ **见下** |
| `LeaseStillHeld` | 想租但还被占着 | ✅ 等 |
| `InstanceError` | 实例生命周期操作失败（启动/停止）| 视情况 |

## `LeaseLost` ≠ 动作没执行

**最重要的一条**：连接在响应回来之前断开时，**浏览器可能已经收到并执行了那个输入**。

所以：
- ❌ 不要因为超时或断线就自动重发写动作（可能付两次款、发两条消息）。
- ✅ 把它当"结果未知"，从**你自己的业务检查点**去查真实状态，再决定继续还是补偿。

```python
try:
    s.click("#pay")
except LeaseLost:
    # 别重试。去查订单状态。
    ...
```

`LeaseLost` 和普通 `ConnectionError` 被刻意分开，就是因为前者绝不能重试、后者可以——
如果混在一起，调用方看到的错误和隧道抖动一模一样，分不清"我不再持有这个浏览器"
和"网络闪了一下"。

## 只重试幂等操作

```python
# 可以重试：导航、读取、查询
s.open(url)  /  s.text()  /  s.query_all(...)

# 不要盲目重试：提交、支付、发消息、删除
s.click("#submit")
```

## 打开调试日志

```python
from sleight import enable_debug_logging

```

## 症状 → 原因

| 症状 | 多半是 |
|---|---|
| `ElementError: is covered at (x,y)` | 元素被遮挡。**错误消息里带挡住它的元素** |
| `ElementError: does not have focus` | 点了不可聚焦的东西（如 `<div>`），后续按键会打给上一个焦点元素 |
| `ElementError: has zero size` | 元素被 CSS 隐藏了 |
| `StaleRef` | 页面导航过，重新 `snapshot()` |
| `wait` 秒回但页面是空的 | 目标会重定向。改等页面自己的东西：`wait=Selector("#x")` |
| `wait` 一直等到超时 | 条件写错，或该条件需要 `track_network=True`（`NetworkIdle`）|
| `block()` 没生效 | 事件泵没跑。`time.sleep()` 期间请求会挂着，改用 `pump_events()` |
| `RuntimeError: Transport is not thread-safe` | 跨线程用了 Session。每线程租自己的实例 |
| 截图/`set_viewport` 尺寸不对 | `set_viewport` 是渲染层覆盖，**改不了 `screen.*`** |
| 插件在 context 里失效 | 无痕 context 不启用扩展，**这是 Chrome 的行为** |
| 换出口 IP 没换 | 只有新建 `BrowserContext` 有效，清缓存没用 |
| 浏览器起不来（Linux）| 加 `no_sandbox=True` |
| 首页就 403 + 验证码 | 出口 IP 信誉，不是指纹。见 [[反检测实战与限制]] |
