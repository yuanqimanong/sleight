# 分布式与实例池

这页解决：同时跑很多浏览器实例、多机聚合、并发怎么写才不出错。

## 一个池，多个来源

```python
from sleight import Pool
from sleight.providers import CloakBrowserManager, Plain, LocalLauncher

pool = Pool([
    CloakBrowserManager("http://10.0.0.1:9000", token=T1, name="hk"),
    CloakBrowserManager("http://10.0.0.2:9000", token=T2, name="sg"),
    Plain("http://127.0.0.1:9222", name="local"),
])
```

`Pool` 是**唯一的实例选择者**，并且全生命周期持有同一个租约表——这是排他性的命脉。
不要每次用的时候现建一个 `Pool`，那样各线程持有不同的锁表，可能同时租到同一个实例。

## Provider

| Provider | 适用 | endpoint 来源 |
|---|---|---|
| `CloakBrowserManager(url, token=…)` | 远程 Manager 管的一队 profile | Manager REST |
| `Plain(url)` | 任何裸 CDP 端点（本机 chrome、browserless）| `/json/version` |
| `LocalLauncher(binary, …)` | 本机自己起的浏览器 | 自己起进程后取 |

## 租用

```python
with pool.lease() as inst:                                  # 任意一个空闲的
with pool.lease(instance_id="5edcc28a-…") as inst:          # 指定 id
with pool.lease(name="Win-US-02") as inst:                  # 指定名字
with pool.lease(where=lambda i: "us" in i.tags) as inst:    # 按标签筛
with pool.lease(timeout=60) as inst:                        # 等最多 60 秒
```

**名字对不上会立刻失败**并列出可见的名字，不是一路阻塞到超时——这是有意的。

批量：

```python
handles = pool.lease_many(4, names=NAMES, timeout=60)   # 部分失败自动回滚已租到的
try:
    ...
finally:
    for h in handles:
        h.close()
```

租约是**协作式排他** + TTL 自动续租。

> **诚实说明**：这是协作式的，**不是** fencing。token 叫 `owner_token` 而不是 fencing token——
> 真正的 fencing 要求受保护资源在每次操作时拒绝旧代次，而 Chrome 不认识你的 租约 token。
> 所以"发命令前检查"永远存在 TOCTOU 窗口。它防的是**你自己的**并发互相踩，
> 不是防恶意抢占。

## 统一数据库租约与浏览器服务

通过 Web 登记 Manager 并配置并发上限。fin、Python 客户端及 MCP 使用用户 token 连接
Sleight 服务。SQLite/PostgreSQL 同时管理配置、身份、配额、心跳与回收，无需 Redis。
租约过期触发清理，确认浏览器停止后才释放名额；失败继续占用并重试。

底层仍可显式使用 `DatabaseLease()` 协调同一数据库的进程：

```python
from sleight import Pool
from sleight.lease import DatabaseLease
pool = Pool(providers, lease=DatabaseLease(), namespace="prod")
```

正式采集建议使用 `sleight.client.ServiceClient`，由服务执行动作并管理浏览器生命周期。
同一 Manager 不要混跑绕过 Sleight 的旧客户端，否则无法保证统一额度。

## 并发的硬约束

**`Transport` 归属创建它的线程。** 跨线程使用会当场抛 `RuntimeError`——是强制的，不是建议。

```python
from concurrent.futures import ThreadPoolExecutor

def task(url):
    with pool.lease() as inst:            # ← 每个线程租自己的实例
        with inst.session(human=True) as s:
            s.open(url)
            return s.title()

with ThreadPoolExecutor(8) as ex:         # Pool 和租约表是刻意共享的
    titles = list(ex.map(task, urls))
```

**规则**：
- ✅ `Pool` 和租约表跨线程共享。
- ❌ `Transport` / `Session` / `InstanceHandle` **不能**跨线程传递。
- 第一次碰 `handle.transport` 的那个线程成为 owner，之后所有 CDP 调用都得在它里面。

## InstanceHandle

一次租用拿到的句柄，管着 session、context、连接和租约的清理顺序。

```python
with pool.lease() as inst:
    inst.session(human=True)      # 新建一个自有 tab 的 Session
    inst.context()                # 新建 BrowserContext（独立 cookie/storage/socket pool）
    inst.targets()                # 列出该实例的 target
    inst.exit_ip()                # 出口 IP
```

## BrowserContext：换出口 IP

```python
with inst.context() as ctx, ctx.session() as s:
    print(ctx.exit_ip())          # 新的出口
    s.open(url)
```
新 context 自带独立 socket pool，这是**唯一可靠**的换出口办法。
清缓存、加唯一查询串、`emulateNetworkConditions` 实测都没用。

⚠️ **换出口与用插件互斥**：无痕 context 里 Chrome 不启用扩展。依赖插件就改成多租几个
profile、各配各的上游代理。见 [[反检测实战与限制]]。

## 三条所有权规则

1. **Pool 是唯一的实例选择者**——别自己挑实例然后绕过它。
2. **一个 Session 同时只属于一个线程**。
3. **`release` 不停实例**——持久化登录态在里面，停了下次要重新登录。停实例是运维动作
   （`sleight profiles stop`），不是任务收尾动作。

## 恢复

```python
pool.recover(instance_id)      # stop → launch → 等就绪
```
**只恢复连接，不重放业务操作**——sleight 不知道哪个 click 是安全的，重放可能意味着付两次款。
从你自己的业务检查点决定怎么继续。
