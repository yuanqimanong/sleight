# 常见问题

按"实际会被问到"排序，答案都基于源码事实。

## 定位与选型

**Q：和 Playwright 什么关系？能一起用吗？**
不是替代，是补充。sleight 是**驱动层**，刻意不做下载、录像、tracing、完整 locator DSL。
能一起用：`sleight.core.human` 是 [sans-io](https://sans-io.readthedocs.io/) 的——它只产出
`(method, params, sleep_after)` 三元组，从不碰 socket——所以可以拿它驱动 Playwright 的
`CDPSession`，只借拟人轨迹。

**Q：能跑 Firefox / Camoufox 吗？**
不能。它们走 Juggler 协议，不是 CDP。整个 Transport/Session/事件模型都建在 CDP 上。

**Q：sleight 能伪装指纹吗？**
不能，也不打算做。指纹是**浏览器内核**的职责。sleight 负责驱动一个反检测内核——
见 [[浏览器内核选择]]。

**Q：headless 是不是更容易被识别？**
现代 `--headless=new` 与有头的差异已经小很多，但仍有差异。做真实任务建议
`launch(..., headless=False)` 配虚拟显示（Xvfb/Xvnc）。真正卡你的往往不是 headless，
是出口 IP——见 [[反检测实战与限制]]。

## 点击 / 等待

**Q：点了但没反应，怎么回事？**
多半是**被遮挡**。sleight 在点击前后各做一次命中校验，被 cookie 横幅、固定头部、遮罩层
盖住时会抛 `ElementError` 并**点名挡住它的元素**——先看错误消息。如果是给的裸坐标
（`Point`/`Box`），那条路径**不做命中校验**，误点了也不报错。

**Q：`wait()` 秒回但页面还是空的？**
旧版本有这个 bug（点击导航后旧 lifecycle 残留），已修：导航纪元跟踪改成常驻，
任何来源的导航都会换纪元。如果仍遇到，八成是**重定向**——一次重定向是两次文档提交，
中间那个也可能发自己的 `DOMContentLoaded`。等页面自己的东西：`wait=Selector("#x")` 或
`wait=Text("…")`，别用 `DomReady`/`Load`。

**Q：`block()` 好像没生效？**
被暂停的请求要靠事件泵拿裁决，而事件泵跑在 `open`/`wait`/`pump_events`/每次 `call` 里。
纯 `time.sleep()` 期间请求会一直挂着。要么用 `pump_events(n)`，要么别 sleep。

## 元素与查询

**Q：静态树（`parse()`）和实时元素（`query()`）怎么选？**
- 要**读很多**元素的文本/属性 → `parse()`，一次抓取 + 内存查询，50 行表格实测快约 18 倍。
- 要**点击/输入** → 实时 `query()`。静态树是只读快照，不能交互，也不反映后续 JS 变更。
- 组合用法：`parse()` 里找到目标 → 用同一个选择器回到 `query()` 去点。

**Q：`query()` 找不到 iframe 里的元素？**
对，`query`/`query_all` 只看主 frame 的普通 DOM。iframe 用
`s.frame_element(iframe选择器, 内部选择器)`，或直接用 `s.snapshot()`——它会把子 frame
（同进程和跨源 OOPIF 都算）合并进来，里面的元素照样有 ref。见 [[Frame与ShadowDOM]]。

**Q：Shadow DOM 里的元素选不中？**
原生 `querySelector` 不穿透 shadow。用 `s.query_shadow(selector)`，它会递归进每个 open
shadow root。closed shadow root 浏览器本身就不给访问，无解。

**Q：Ref 什么时候失效？**
Ref 由 `(loaderId, backendNodeId)` 做键。**页面一导航就全部失效**，`snap.ref("e1")` 抛
`StaleRef`——这是有意的，避免点到"此刻恰好在那个位置"的另一个元素。重新
`s.snapshot()` 即可。同一节点跨多次快照拿到的是**同一个** ref。

**Q：CSS 选择器为什么有些写法不支持？**
`parse()` 的内建引擎是零依赖的 CSS **子集**：类型/`#id`/`.class`/`*`/属性各算符/复合/
后代/子(`>`)/并集(`,`)。**不支持**兄弟组合子(`+` `~`)和伪类(`:nth-child` 等)。
要更强的表达力就调用 `parse(xpath=True)` 使用 XPath，默认安装已包含所需依赖。
注意：**实时** `query()` 走浏览器原生 `querySelectorAll`，伪类、兄弟组合子全都支持。

## 实例与并发

**Q：多线程怎么用？**
`Transport` **归属创建它的线程**，跨线程使用会当场抛 `RuntimeError`（是强制的，不是建议）。
正确姿势：**每个线程 `lease()` 自己的实例**。`Pool` 和租约表是刻意共享的。

**Q：能接管我已经开着的 Chrome 吗？**
可以连（`connect(...)`），但默认**不接管已有 tab**——它会新建自己的 tab，退出时关掉。
要接管特定 tab 得显式 `Session.attach(transport, target_id)`。
另注意：Chrome 136+ 对**默认用户目录**禁用了 `--remote-debugging-port`，所以你日常那个
Chrome 通常连不上，需要用独立的 `--user-data-dir` 启动。

**Q：换出口 IP 为什么必须用 context？**
隧道按 TCP 连接分配地址，而 Chrome 复用 keep-alive socket，所以整轮跑下来钉在同一个 IP。
**只有新建 `BrowserContext`（自带 socket pool）能可靠打破**。清缓存、加唯一查询串、
`emulateNetworkConditions` 实测全都没用。

**Q：为什么插件在 context 里不生效？**
`Target.createBrowserContext` 建的是**无痕**上下文，Chrome 默认不在无痕里启用扩展。
同一个 profile 同一个 URL：`chrome-extension://<id>/…` 在默认 context 打得开，在新 context
里返回 `ERR_BLOCKED_BY_CLIENT`。所以**换出口和用插件互斥**——依赖插件就多租几个 profile、
各配各的上游代理。

## 运维

**Q：数据存在哪？怎么完全卸载？**
启动目录的 `data/`：`control.db`（统一配置与运行账本）、`browsers/`（内核）、`native/`（浏览器登录态）、`secret.key`（加密密钥）。
`$SLEIGHT_HOME` 可改。卸载库使用 `pip uninstall sleight`，数据目录独立保留。

**Q：能在 CI 里跑吗？**
能。仓库自己的 CI 就装 chromium 并跑 `pytest -m integration`。要点：
容器里跑给 `no_sandbox=True`；用 `SLEIGHT_TEST_CHROMIUM` 指定 binary；
`SLEIGHT_HOME` 指到临时目录做隔离。

**Q：Web 界面能开到公网吗？**
**不建议**。没有 TLS、没有用户体系、token 会进 URL 和 localStorage。要远程访问用
`sleight tunnel` 走 SSH 隧道。见 [[Web界面教程]]。

## MCP

**Q：MCP server 起不来怎么排查？**
1. 必须给 `SLEIGHT_CDP_URL`（连已有浏览器）**或** `SLEIGHT_BROWSER`（起本机内核），
   两个都没有会**启动即退出**并打印提示。
2. stdout **只走协议**，日志全在 stderr——看 MCP host 的 stderr 日志。
3. 先手动跑一遍确认：`SLEIGHT_CDP_URL=http://127.0.0.1:9222 sleight-mcp`，
   然后粘一行 `{"jsonrpc":"2.0","id":1,"method":"ping"}` 回车，应该回 `{"result":{}}`。

**Q：模型点不动元素？**
先 `browser_observe`（snapshot）拿 ref 再 `browser_act`。没拍过快照就用 ref 会返回
"no snapshot yet"。页面导航后快照作废，要重拍。图标类/canvas UI 用 `coordinate` 逃生舱。
