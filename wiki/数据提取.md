# 数据提取

这页解决：抓正文和字段、批量抓表格、用什么查询语法。

## 复用浏览器请求接口

登录后读取同站接口时，不必反复渲染页面或新建实例：

```python
s.open("https://your-site.example/account")
response = s.fetch("/api/items", timeout=15, max_bytes=256 * 1024)
if response.ok:
    data = response.json()
```

请求在当前页面的 `window.fetch` 中执行，复用浏览器 Cookie（含 HttpOnly）、代理和连接。
既可用完整 HTTP(S) 地址，也可用相对地址；`ServiceClient` 的远程会话同样支持。
返回 `FetchResponse`，字段为 `url/status/status_text/headers/text/redirected`，提供 `.ok` 和 `.json()`。
`headers` 仅含浏览器允许页面读取的响应头，`.json()` 要求响应是有效 JSON。

SDK 支持 GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS；POST 等可传文本 `body` 和 `headers`。
请求体最多 1 MiB，GET/HEAD 不接受请求体。Cookie、User-Agent、Referer、Sec-* 等头由浏览器管理，
不能手工覆盖；导航来源可通过 `open(..., referrer="https://source.example/")` 显式提供。

默认超时 30 秒，可设 0.1–120 秒；响应最多 1 MiB，可调低 `max_bytes`。
流式读取时达到上限立即取消，抛 `ResponseTooLarge`；超时抛 `sleight.errors.TimeoutError`。
HTTP 4xx/5xx 保留响应，网络/CORS/CSP 失败抛 `sleight.errors.ProtocolError`，不自动重试。
返回 UTF-8 文本，暂不支持二进制下载；仍受 CORS/CSP 和 SameSite Cookie 规则约束。
返回数据未经过页面渲染，需要最终 DOM 时继续使用 `extract_document()` 或 `parse()`。

## 抓正文与常用字段

```python
doc = s.extract_document()
```

在**页面内**做（跑一段 JS），零 Python 依赖，吃的是 JS 执行后的最终 DOM——
登录后、动态渲染的内容都在，这是纯静态 HTML 抽取库吃不到的。

### `ExtractedDocument` 字段

| 字段 | 含义 |
|---|---|
| `url` | 抽取时的 `location.href` |
| `title` | `og:title` → `twitter:title` → `document.title`（按序取第一个有值的）|
| `lang` | `<html lang>` |
| `byline` | 作者：`author` / `article:author` / `twitter:creator` |
| `excerpt` | 摘要：`og:description` / `twitter:description` / `description` |
| `site_name` | `og:site_name` |
| `published` | `article:published_time` 等 |
| `image` | `og:image` / `twitter:image` |
| `canonical` | `<link rel=canonical>` |
| `text` | 清洗后的正文纯文本 |
| `html` | 清洗后的正文 HTML（去掉 script/style/noscript/iframe/svg）|
| `links` | 正文里的链接 `[{href, text}]`（上限 200 条）|
| `metadata` | 所有 `<meta name\|property>` 的原始键值 |
| `json_ld` | 所有 `application/ld+json` 解析后的对象 |
| `char_count` / `word_count` | 字符数 / 空白分词数（中日韩看前者）|
| `link_density` | 选中正文块的链接文字占比（0~1，越高越像导航/列表）|
| `quality` | **工程质量分**（0~1），**未校准，不是概率** |
| `low_quality` | `quality < 0.3` |
| `engine` | 产出该结果的引擎名，内建是 `"builtin"` |

### 正文是怎么选出来的

readability 式密度打分：
1. 先找结构标签 `article` / `main` / `[role=main]`，取文本最长且 >200 字的。
2. 找不到就对所有 `article,section,div,td,li,main` 打分：
   `文本长度 × (1 - 链接密度) + 标点数 × 10`，跳过链接密度 >0.5 的。中英文标点都计入。
3. 还是没有就用 `body`。

**回退规则**：抽出来的正文短于 `min_length`（默认 200 字符）时，回退整页 `text()`——
宁可多给上下文，也不给一段抽错的短正文。

**质量分**：`min(1, 字符数/800) × (1 - 链接密度)`。它是工程信号不是概率——
低分意味着"多半没抽准，建议人看一眼或换别的方式"。

实测参考：一篇正常新闻 quality ≈ 0.55–0.95；一个 40 条链接的列表页 `link_density` 0.93、
`low_quality=True`（诚实地告诉你没抽到干净正文，而不是硬编一段）。

### 外部引擎

`engine` 字段是留给适配器的插点。想接 trafilatura / readability-lxml 这类**外部** Python
引擎（尤其做纯静态 HTML 批量抽取或跑离线基准），自己适配到 `ExtractedDocument` 即可。
本模块**零外部依赖**，不强制。

> 选型提示：调研显示 Trafilatura 在英文文章上 F1 领先，但在**中文**页面上
> （SIGIR 2025 多语种评测）precision 掉到 0.501、F1 0.555，反而低于 Readability 的 0.672。
> 要做中文就别无脑用 Trafilatura。

## 批量只读：静态快查

要读很多元素时，实时 `Element` 每次查找/读属性都是 CDP 往返，N 个元素 O(N) 次。
`parse()` 换成"**一次抓取 + 之后纯内存查询**"：

```python
dom = s.parse()
names  = [e.text for e in dom.query_all("tr.row td.name")]
prices = [e.text for e in dom.query_all("tr.row td.price")]
```

50 行表格实测 **8ms vs 152ms，约 18 倍**。

**签名**：`parse(*, pierce_shadow=False, xpath=False) -> StaticElement`

| 参数 | 作用 |
|---|---|
| `pierce_shadow=True` | 把 open Shadow DOM 内容也内联进来一起查（多一次页面内序列化）|
| `xpath=True` | 用 lxml 建树，解锁 `.xpath()`（默认安装已包含依赖）|

**边界**：静态树是**快照**——只读、不能交互、不反映后续 JS 变更。
查到目标要点击/输入，用同一个选择器回到实时 `s.query()`。

### `StaticElement` 读取

| 成员 | 说明 |
|---|---|
| `tag` / `attrs` | 标签名 / 属性字典 |
| `attr(name)` | 单个属性值，没有返回 `None` |
| `text` | 本元素及所有后代的文本（**按文档顺序**拼接、空白规整）|
| `inner_text` | 仅**直属**文本（不含后代元素里的）|
| `children` / `parent` / `iter()` | 树导航 |
| `query(sel)` / `query_all(sel)` | CSS 查询 |
| `xpath(expr)` | XPath（需 `xpath=True` 建的树）|

> 文本顺序是对的：`<p>some <b>bold</b> text</p>` → `"some bold text"`，
> 不会错成 `"some text bold"`。

## 查询语法

### CSS 子集（零依赖，默认可用）

| 语法 | 例子 |
|---|---|
| 类型 / `#id` / `.class` / `*` | `li` `#main` `.row` `*` |
| 属性存在 | `[data-k]` |
| 属性相等 | `[name=q]` |
| 前缀 / 后缀 / 包含 | `[href^=/api]` `[href$=.png]` `[href*=user]` |
| 空白分隔词 | `[class~=hot]` |
| 复合 | `div.a#b[x=y]` |
| 后代（空格）| `#main a` |
| 直接子（`>`）| `ul.list > li` |
| 并集（`,`）| `a, input` |

**不支持**：兄弟组合子（`+` `~`）、伪类（`:nth-child` `:not` 等）、XPath。
需要这些就用下面的 XPath，或走实时 `s.query()`（浏览器原生，全都支持）。

### XPath（默认安装可用）

默认安装已包含 lxml；用 `xpath=True` 选择 XPath 后端：
```python
dom = s.parse(xpath=True)

dom.xpath("//tr[3]/td[@class='name']/text()")        # 位置谓词 → ['Item 3']
dom.xpath("//tr[last()]/td[@class='price']/text()")  # last()
dom.xpath("//li[contains(@class,'row')]")            # contains()
dom.xpath("//input/preceding-sibling::ul")           # 轴

row = dom.xpath("//tr[@class='row'][2]")[0]
row.xpath(".//td")                                   # 相对本元素求值
dom.query_all("tr.row td.name")                      # CSS 在同一棵树上照常工作
```

**返回类型规则**（原生 lxml 语义，不硬掰）：
- 元素结果 → `StaticElement`
- `text()` / `@attr` → `str`
- 注释、PI 等 → 跳过

同一棵树上 CSS 和 XPath 都能用，`text`/`attr`/`parent` 行为完全一致（有一致性对拍测试保证）。
对默认 CSS 树调用 `xpath()` 会提示用 `parse(xpath=True)` 建树。

## 完整例子：抓一个表格

```python
from sleight import launch
from sleight.core.types import Load

with launch("chromium", no_sandbox=True) as s:
    s.open("https://example.com/table", wait=Load())

    dom = s.parse()
    rows = []
    for tr in dom.query_all("table#data tbody > tr"):
        cells = tr.query_all("td")
        rows.append({
            "name":  cells[0].text,
            "price": cells[1].text,
            "link":  (a.attr("href") if (a := tr.query("a")) else None),
        })
    print(len(rows), rows[:3])
```
