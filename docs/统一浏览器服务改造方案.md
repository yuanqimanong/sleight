# Sleight 统一浏览器服务改造方案

日期：2026-10-09。本方案已完成本地实现；验收结果见 [统一服务本地测试报告](统一服务本地测试报告.md)。尚未部署生产或发布 PyPI。

后续需求单独记录在 [后续开发清单](后续开发清单.md)：Cloak 临时实例应提供对应 Manager 浏览器界面的清晰入口，本轮仅记录。

## 1. 目标与范围

- Sleight 安装后只运行一个 Python Web 服务，包含 Web、API、HTTP MCP 和回收器。
- Web、Python 客户端、AI MCP 使用同一套用户身份、权限、浏览器执行和操作记录。
- 原生浏览器与 Cloak Manager 共用会话入口。Manager 地址和凭据不交给业务客户端。
- 默认 SQLite；配置 PostgreSQL 时切换到 PostgreSQL。两者使用相同逻辑表结构和迁移版本。
- 配置、用户、任务、配额、租约、心跳、回收记录由数据库管理，移除 Sleight 的 Redis 依赖和 extra。
- 公开安装形式最终仅保留 `pip install sleight`，包含 UI、XPath、PostgreSQL 驱动和服务客户端所需依赖。
- 依赖按开发时最新稳定版本更新，验证 Python 3.11 和依赖之间的兼容性后锁定；同步 uv 与前端锁文件。
- 保留现有 Vue 新野兽派前端；GitHub 编译静态文件并装入 wheel/sdist，运行机器不需要 Node。
- 首版以单服务、单 worker 交付。PostgreSQL 配额实现须具备跨进程一致性；多服务会话路由和高可用不因换数据库自动获得。
- 本轮不修改 Cloak Manager 自身的数据库实现，不重构 fin 的业务数据表和调度框架，不改 pyp 导航位置。

## 2. 改造前的基础（历史状态）

- Sleight 0.6 已实现浏览器部署、Manager Docker 导入/升级/备份/回滚、插件下发、代理模板、原生预览和官方 Manager 监控。
- 配置仍分布于 `sleight.db`、`runtime.db`、`jobs.db` 和部分凭据文件；只有全局管理口令。
- SDK/MCP 仍可以直接连接浏览器；fin 目前直接调用 Manager、SDK 和 Redis 治理逻辑。
- pyp 已有管理员导航及 HTTP/SSE/WebSocket 反代，但所有用户都转发同一个服务口令。
- 前端已移到 `frontend/tests/` 集中测试；无用 pytest 临时目录已清理。
- 发布工作流已在本地补上前端测试、编译、wheel/sdist 页面资源校验，尚未推送或发布。

## 3. 架构与执行接口

调用链：Web / Python 客户端 / MCP → Sleight 用户鉴权 → 会话执行器 → 原生浏览器或 Manager。

- 使用版本化服务接口，覆盖环境与模板选择、会话申请、操作、事件、心跳、取消和结束。
- SDK 提供远程会话，尽量保持 fin 已使用的 Session 方法与异常类型，浏览器动作在服务端执行。
- 每个会话使用固定执行线程和串行命令队列。现有 Transport 有线程归属约束，不能让不同 HTTP 请求线程直接访问同一对象。
- 拟人轨迹、等待和输入节奏在服务端执行，避免经 VPN 为每个鼠标移动产生往返请求。
- 必须覆盖导航、刷新、点击、滚动、JavaScript、查询、Cookie、清理站点数据、资源屏蔽、资源捕获、事件泵和 fin 使用的受控 CDP 命令。
- 插件会话保持默认 browser context；固定 profile 的 Cookie 和用户目录按策略保留，不因远程会话适配而强制切成无插件的隔离 context。
- Python 回调不序列化成远程代码。SDK 在客户端处理回调；服务端支持结构化过滤和有界事件流，明确溢出与断连错误。
- 限制队列、捕获资源、截图、结果大小和日志保留量，避免后台管理能力自身持续占用内存。
- 不向客户端暴露 Manager token 或未经授权的浏览器连接。原始 CDP 能力按权限限制在所属会话内。
- HTTP MCP 使用标准 Streamable HTTP 并优先采用官方 SDK，挂在同一 Python 服务中；验证版本协商、工具调用和会话失效。stdio MCP 可作为连接该服务的薄客户端，不再自行启动远端业务浏览器。

## 4. 数据库与数据迁移

采用统一数据模型、仓储层和版本化迁移。SQLite 与 PostgreSQL 的逻辑表名、字段、关系一致；自增、类型和锁语法由适配层处理。

主要实体：

| 实体组 | 内容 |
|---|---|
| 身份 | users、tokens、external_identities |
| 环境 | hosts、deployments、templates、profiles、secrets |
| 运行 | sessions、resource_limits、leases、jobs |
| 记录 | job_events、audit_events、schema_version / settings |

- 默认数据库放在 `SLEIGHT_HOME` 管理的数据目录；使用 `SLEIGHT_DATABASE_URL` 指定 PostgreSQL。
- PostgreSQL 使用独立数据库或专用 schema，避免混入 fin_sys / pyp_sys 的表。
- SQLite 使用事务和 WAL；PostgreSQL 使用事务、行锁和唯一约束。数据库时间用于租约判定，进程内预算使用单调时钟。
- SQLite/PostgreSQL 均能保存运行管理数据。文件系统继续保存浏览器用户目录、插件、备份与必要的加密密钥。
- token 只保存哈希；需要再次使用的 Manager、代理和执行端凭据加密保存，密钥独立于数据库。
- 导入现有三个 SQLite 数据库及配置/执行端凭据文件，保留记录标识、环境、模板和历史；未带用户归属的旧记录分配给迁移管理员。
- Manager 必需的 Compose `.env` 作为受控部署产物保留，不把它误当成需要删除的缓存。
- 提供可检查的备份/导入流程和 SQLite → PostgreSQL 迁移命令。切换数据库时暂停写入，校验数据与凭据可用后再启动。
- 配置数据可以迁移；活跃浏览器会话不承诺跨数据库在线迁移。升级前先排空或停止会话。
- 数据库升级失败不继续运行不兼容服务。默认首次安装可初始化；已存在数据库的升级须有备份与明确诊断。

## 5. 用户、token 与权限

- 首次初始化创建管理员，管理页可创建用户和 token。token 明文仅创建时返回一次。
- 支持 token 过期、撤销、轮换和用途范围；用户可拥有多个 token。
- 用户关联默认环境与模板，因此 fin 基础配置只需地址与 token。
- 管理员负责主机、Docker 部署、升级和用户权限；执行用户操作被授权的模板、实例及会话。
- 日志记录用户、凭据标识、来源、任务/会话标识、动作、耗时、结果和错误摘要；不记录 token、完整代理凭据或 Cookie 明文。
- token 撤销与用户禁用对 HTTP、事件流、WebSocket 和 MCP 一致生效。运行中的自动会话进入可追踪的停止/回收流程。
- fin 使用专用执行 token；pyp 使用有受限身份委托能力的专用 token，两者独立轮换。
- pyp 委托由 Sleight 验证，使用可信接入身份和稳定外部用户标识映射；不能仅信任客户端传来的用户 ID 头。

## 6. 替代 Redis 的运行管理

建议状态流转：reserved → starting → running → cleanup_pending → cleaning → released；固定实例会话结束后保留 profile 数据。

- 配额同时计入预留、启动中、运行中和尚未确认清理成功的实例。
- 使用事务申请全局环境配额及用户配额；同一实例仅能被一个有效会话持有。
- 创建/启动使用幂等请求标识。请求超时、客户端重试和响应丢失不得生成多个浏览器。
- 租约带心跳、版本和执行端归属；旧客户端的迟到请求不得修改已转交的会话。
- 客户端离线、任务取消、进程强杀和服务重启后，由独立回收器恢复处理。
- 租约过期只触发清理。确认浏览器停止/删除后才能释放名额，清理失败继续占用并持久重试。
- 对账 Manager 中真实运行的浏览器，将外部实例计入容量；无法证明归属的实例只提示，不自动删除。
- 原生进程使用执行主机、PID 和启动时间核实身份，不跨机器直接用客户端 PID 判断存活。
- 数据库不可用时拒绝新建和扩容，不降级到无配额模式；恢复后进行状态对账。
- 保留 Docker 内存、CPU、PID、共享内存硬限制。数据库并发额度不能替代容器资源限制。
- 完成两种数据库的容量、租约、回收测试后，删除 RedisLedger、RedisLease、extra、相关配置、文档与已被替代的测试。

## 7. Web、部署与监控

- 延续当前视觉与交互，增加用户、token、默认环境/模板、额度、会话、回收状态和操作记录页面。
- 环境仍支持 Windows Docker Desktop、Linux Docker、原生浏览器及已实现的远程执行端接入。
- 保留部署前检查、固定验证过的镜像、导入现有环境、完整数据备份和升级失败恢复。
- 插件推送源是控制台所在机器的解压目录；Manager 使用容器内部路径，原生浏览器使用所属执行机器路径。
- Web 模板作为任务默认设置，允许有权限的任务覆盖动态 seed / SID 等字段；不让 fin 继续维护重复的插件路径和浏览器代理模板。
- 保留 MV3 校验、插件应用后的重启提示及实际页面效果验收。
- 原生浏览器提供有界刷新预览；Manager 使用官方监控，由 Sleight 验证用户后反代。
- Web 的用户范围、按钮可用状态、配额不足、执行失败、等待清理和凭据失效必须有明确提示。

## 8. fin 配套改造

- 配置库新增 `sleight_upstream`、`sleight_token`，代码属性对应 `SLEIGHT_UPSTREAM`、`SLEIGHT_TOKEN`。
- 保留旧 `cloak_*` 值，不在共享生产库中直接修改旧键；新增记录不修改原配置表结构。
- 同时增加本地环境变量覆盖，优先级为显式本地环境变量 → 当前环境数据库配置。地址与口令不写入代码默认值。
- 更新基础远程爬虫入口和 SDK 远程会话适配；站点业务解析尽量保持原样。
- 迁移动态指纹、代理 SID、固定实例兜底、插件、Cookie、资源捕获、请求屏蔽、超时预算和取消行为。
- 删除 fin 对 Manager 的直接治理、跨机 PID 清理及 Sleight Redis 使用；只关闭自己的会话。
- 新服务模式中 Sleight 不可达时明确失败，不能自动绕过服务退回直连 Manager。
- 保留 DEBUG 仅手动执行的行为；本地联调用独立 Manager/数据目录，不修改共享 base 配置。
- 更新依赖、锁文件与 vendor wheel。发布稳定后再决定将来源切到 PyPI，不在联调中使用不明确的最新版本。
- fin 的通用 Redis 数据库适配器另行核对；本轮只删除 Sleight 相关依赖用途。
- 新增配置说明、升级/回滚说明和受保护的本地联调步骤。手动任务仍可能写共享业务数据库，真实验收先使用独立 fixture。

## 9. pyp 配套改造

- 导航、`/sleight-console`、管理员入口、iframe 和反代地址保持可复用。
- `SLEIGHT_UPSTREAM` 仍指 Sleight 服务；`SLEIGHT_TOKEN` 改为 Sleight 签发的受限 pyp 接入 token。
- pyp 验证自己的管理员身份后，从 Sleight 换取该实际用户的短期委托凭据；Sleight 记录实际操作者。
- 长期口令留在 pyp 后端，不把 pyp JWT 或用户 Cookie 传给 Sleight，不允许浏览器自行指定委托身份。
- HTTP/SSE/WebSocket 使用一致的委托身份、过期和撤销策略；调整必要的身份接口放行及错误反馈。
- 校验反代子路径、静态资源、Cookie 续期、WS 重连、MCP 接口与 token 管理页面的兼容。
- 无需重复新增导航迁移。用户映射优先存 Sleight，避免在 pyp 另维护一套浏览器用户表。
- 更新 `.env.example` 和 `deploy/README.md` 的 token 说明，删除 Sleight 共享 Redis 要求。

## 10. 兼容、切换与回滚

- 新增配置记录兼容旧 fin；不能据此推断新旧 SDK/服务协议自动兼容，需显式版本检查和完整配套验收。
- 保留旧数据和旧配置供回滚。旧的全局管理口令作为迁移引导凭据处理，新模型不能继续让所有用户共享同一权限身份。
- 测试与旧线上环境使用不同 Manager 容器、端口、数据目录和存储范围。
- 同一个 Manager 不同时混跑旧的直连客户端和新的受控客户端；旧调用绕过新数据库配额会破坏容量保证。
- 正式切换顺序：停止旧浏览器任务 → 备份数据 → 启动并验收新 Sleight/Manager → 更新 pyp/fin → 单任务小并发验证 → 恢复调度。
- 回滚顺序：停止新任务 → 关闭或回收新会话 → 恢复匹配的服务代码、数据、配置及 fin wheel/锁文件 → 切回旧入口。
- Manager 回滚需要匹配镜像和完整数据备份，不能只换镜像；旧部署备份保留到验收结束。

## 11. 开发顺序与交付门槛

| 阶段 | 开发内容 | 进入下一阶段前必须满足 |
|---|---|---|
| 1 | 统一数据模型、迁移、用户、token、默认环境 | SQLite/PG 一致；旧配置可导入；凭据和权限正确 |
| 2 | 数据库配额、租约、会话执行器、回收 | 超额启动被拒绝；重复请求不重复创建；故障后可回收 |
| 3 | 远程 SDK、事件流、HTTP MCP、stdio 客户端 | fin 所需方法与错误语义覆盖；线程与事件行为正确 |
| 4 | Web 用户/会话页面、部署、插件、监控 | 现有部署和可视化能力无回退；用户范围和错误提示清晰 |
| 5 | fin/pyp 适配、Redis 删除、锁文件和文档 | 三项目无 Redis 链路通过；旧配置保留；本地覆盖有效 |
| 6 | Windows/Linux 真环境验收、打包验证 | SQLite/PG、Docker、插件、SDK、MCP、pyp 反代全部通过 |

## 12. 测试与验收

- Python 使用 uv 管理依赖并运行 tests；前端使用 `frontend/tests`。临时产物使用系统临时目录，不增加成批根目录 pytest 文件夹。
- 同一套仓储、权限、额度、租约和清理测试分别运行 SQLite 与真实 PostgreSQL。
- 并发申请最后一个名额、重复请求、创建成功但响应丢失、心跳迟到、token 撤销、任务取消、数据库短时故障、服务重启和清理失败必须覆盖。
- 验证同一会话串行执行，不同会话互不串数据；普通 token 不可访问他人的 Cookie、实例、模板、监控及敏感部署接口。
- 真实本地测试使用独立 PostgreSQL 容器、Manager 容器、数据卷、插件和 HTTP fixture，不访问共享生产数据库。
- Windows 验证原生浏览器；Docker Desktop 验证 Linux Manager、MV3 插件、代理、监控和无 Redis 回收。
- 完成 fin 的 Reuters/WSJ/Bloomberg 等浏览器能力 fixture 回归，保留 DEBUG、预算与取消测试。
- pyp 验证委托用户归属、管理员撤销、HTTP/SSE/WS、子路径、续期及长期 token 不泄漏；遵照此前要求不新增持久测试目录，使用临时隔离脚本。
- 干净环境安装 wheel，只启动 Python 验证 Web/API/SDK/MCP；检查 wheel/sdist 页面资源及元数据均不再声明 redis extra。
- 发布流程做前端测试/编译、Python 检查、打包与资源一致性校验；本地验收不触发 GitHub tag 或 PyPI 发布。
- 外部网站成功率另外通过受控小样本验收；本地 fixture 通过不等同于 Reuters 实站成功率保证。

## 13. 首版验收结论要求

1. 一个 Python 服务可供 Web、代码和 AI MCP 使用；无需 Node 或 Redis 服务。
2. SQLite/PG 均保存配置、用户和运行管理状态，权限与容量行为一致。
3. 新模式客户端不持有 Manager 地址、口令和插件路径，通过用户默认配置选环境。
4. 容量不超配，任务故障和服务重启后浏览器可追踪、可回收。
5. 浏览器插件、代理、Cookie、指纹、捕获和监控能力保持有效。
6. pyp 操作可追溯到实际用户，fin 使用独立执行身份，本地测试不污染线上配置。
7. 新增配置不覆盖旧配置；配套升级、数据迁移和回滚步骤可复现。
