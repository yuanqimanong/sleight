## 1. 这个库解决什么问题

浏览器层的反检测已经有成熟方案（CloakBrowser 的源码级 Chromium patch、Camoufox 的
Juggler patch），它们解决**指纹**——浏览器长什么样。没有人解决**行为**——它怎么动。

- Playwright / Puppeteer 的默认鼠标是**瞬移**；`mouse.move(steps=N)` 是**匀速直线**，
  零抖动、加速度恒为 0。匀速直线本身就是特征。
- **浏览器不会替你补轨迹。** 即便浏览器侧开了 humanize，外部 CDP 客户端在 press 与
  release 之间产生的 `mousemove` 事件是 **0 条**（实测，不是推测）。
- 轨迹库生态在 JS 侧（`ghost-cursor`），Python 侧移植维护薄弱。
- Crawlee for Python 的 `BrowserPool`
  [不支持远程浏览器](https://github.com/apify/crawlee-python/issues/1743)。

sleight 补的就是这个位置：**Python + 远程 CDP + 拟人行为 + 实例租约**。

### 做什么 / 不做什么

| 做 | 不做 | 不做的话交给谁 |
|---|---|---|
| 连接任意 CDP 端点 | 数据抽取 / 清洗 | parsel / pyquery / selectolax |
| 导航、类型化等待、读渲染后 DOM | 定时调度、队列、去重、入库 | APScheduler / Celery |
| 拟人鼠标 / 键盘 / 滚轮 | 完整的定位 DSL | Playwright |
| 实例发现、跨 Manager 聚合 | 指纹伪装 | 浏览器自己的事 |
| 协作式排他租约 | iframe / OOPIF / Shadow DOM 穿透 | Playwright |
| 故障分类与幂等恢复 | 严格 fencing（强制驱逐旧持有者） | 需要在浏览器节点部署转发 Agent |
| | WebDriver BiDi、Firefox | Playwright-Firefox |

**与 Playwright 的关系是补位，不是替代。** sleight 的 `human` 模块是
[sans-io](https://sans-io.readthedocs.io/) 的——它只产出 `(method, params, sleep_after)`
三元组，从不碰 socket，所以它可以直接驱动 Playwright 的 `CDPSession`。

## 2. 安装

```bash
pip install sleight
```

用 uv：

```bash
uv add sleight
```

可选依赖：

| extra | 装什么 | 什么时候要 |
|---|---|---|
| `redis` | `redis>=5` | 跨进程 / 跨机租约 `RedisLease`，见 [5.5](#55-多线程并发跑一批任务) |
| `dev` | `pytest` `ruff` | 开发与测试 |

```bash
pip install "sleight[redis]"
```

从源码装：

```bash
git clone git@github.com:yuanqimanong/sleight.git
cd sleight
uv sync --extra dev
uv run pytest
```

**依赖只有一个是有意为之。** 实测三方 HTTP 库的代价：`urllib.request` 装 0 个包，
`httpx` 装 6 个，`niquests` 装 7 个（含两个 Rust 编译扩展）。Provider 每分钟只发几个
HTTP 请求，用不上连接池和 HTTP/2。

## 3. 快速开始

### 最短的能跑的代码

先起一个开了调试端口的 Chrome：

```bash
chrome --remote-debugging-port=9222
```

然后：

```python
from sleight import connect

with connect("http://127.0.0.1:9222") as s:   # 自建 tab，退出自动关闭
    s.open("https://example.com")
    print(s.title(), len(s.content()))
```

### 加上拟人

```python
from sleight import connect, Text

with connect("http://127.0.0.1:9222", human=True) as s:
    s.open("https://example.com", wait=Text("Example Domain"))
    s.hover("h1")                      # 贝塞尔轨迹 + 手抖，几十个 mousemove
    s.click("a")                       # 落点是 bbox 内的截断高斯，不是正中心
```

### 连 CloakBrowser Manager

```python
from sleight.providers import CloakBrowserManager

mgr = CloakBrowserManager("http://127.0.0.1:19000", token="…")

with mgr.lease() as inst:              # 排他租约，退出自动释放
    with inst.session(human=True) as s:
        s.open("https://example.com")
        s.type("#email", "user@example.com")
        s.click("#submit")
```

## 4. 五层结构

```
Provider          发现 / 状态 / 启停 / Endpoint。不做选择，不持锁。
   ↓
Pool              唯一的实例选择者。持有长期 LeaseStore。产出 InstanceHandle。
   ↓
InstanceHandle    持有租约，跟踪自己创建的 Session，负责关闭顺序。
   ↓
Session           默认创建自有 tab。管 target / sessionId / transport。
   ↓
Transport         call / send_no_wait / flush。
   ↑
Human             纯算法。不接触 Transport / Provider / Lease。
```

| 层 | 职责 | 关键约束 |
|---|---|---|
| **Provider** | 告诉你有哪些实例、它们的状态、CDP 地址在哪，以及怎么启停 | **没有 `lease()`**。`mgr.lease()` 是转发到懒建单例 Pool 的便利方法 |
| **Pool** | 唯一的选择者。first-free，按 provider 打散起始下标 | **全生命周期持有同一个 LeaseStore**——锁表归属单次调用的话排他直接失效 |
| **InstanceHandle** | 一次租用。懒建 WS 连接，跟踪 Session | 关闭顺序硬性：Session → 续租线程 → WS → `provider.release()` → `lease.release()` |
| **Session** | 一个 tab 上的操作。**不是线程安全的，也不需要是** | 一个实例同时只给一个 Session。跨线程用会当场 `RuntimeError`，见 [5.5 的并发契约](#55-多线程并发跑一批任务) |
| **Human** | 纯算法，不 import transport / provider / lease | 产物是事件三元组，谁发、发到哪它不知道 |

### 三条容易踩的所有权规则

1. **一个实例同时只给一个 Session。** 两个客户端同时控一个浏览器会互相切页面。
   并发的正确写法是每个线程 `lease()` 自己的实例（见 [5.5](#55-多线程并发跑一批任务)）。
2. **`release()` 默认不停实例。** 持久化登录态在浏览器里，停了下次要重新登录。
   停实例是运维动作，用 `mgr.stop(id)` 显式做。
3. **`Session` 默认新建自己的 tab，退出时关掉它。** 接管既有 tab 必须显式
   `inst.attach(target_id)`，那种 Session 退出时只 detach，不关页面。

## 5. 实战场景

### 5.1 本地 Chrome 跑通第一个脚本

调试期最方便的后端就是本机 Chrome。

```bash
# macOS
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  --remote-debugging-port=9222 --user-data-dir=/tmp/sleight-profile

# Windows
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --remote-debugging-port=9222 --user-data-dir=%TEMP%\sleight-profile

# Linux
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/sleight-profile
```

> `--user-data-dir` 一定要给。不给的话 Chrome 会复用你日常那个 profile，调试脚本
> 就在你自己的登录态上乱点。

```python
from sleight import connect, Selector

with connect("http://127.0.0.1:9222", human=True) as s:
    s.open("https://example.com", wait=Selector("h1"))

    print("标题:", s.title())
    print("地址:", s.url())
    print("正文前 80 字:", s.text()[:80])

    link = s.query("a")
    if link:
        print("链接几何:", link.box())
        s.click(link)                            # 跟随 Session 默认（拟人）
        s.wait(Selector("body"), timeout=10)

    s.screenshot("shot.png")
```

`connect()` 也接受直接的 `ws://` 浏览器级端点：

```python
with connect("ws://127.0.0.1:9222/devtools/browser/abc-123") as s:
    ...
```

`Plain` provider 还支持带鉴权头的裸端点（browserless 那类）：

```python
from sleight.providers import Plain

p = Plain("https://chrome.browserless.io", headers={"Authorization": "Bearer …"})
with p.lease() as inst:
    with inst.session() as s:
        s.open("https://example.com")
```

### 5.2 只有 Manager 地址和 token，怎么开始

**够了。** 实例发现、WS 地址拼装、Bearer 握手头、未运行 profile 的拉起，
`CloakBrowserManager` 全包了。

```python
from sleight.providers import CloakBrowserManager

mgr = CloakBrowserManager(
    "http://127.0.0.1:19000",
    token="…",                 # 不给就读环境变量 SLEIGHT_CLOAK_TOKEN
)
```

| 构造参数 | 说明 |
|---|---|
| `base_url` | Manager 根地址。尾部斜杠会被去掉 |
| `token` | Bearer token。**必需**——WS 握手不带它直接 403 |
| `name` | 池内唯一的 provider 名，默认 `"cloakbrowser"`。也是 uid 前缀 |
| `timeout` | HTTP 超时，秒，默认 15 |
| `ca_bundle` | 自签证书的 CA 文件路径。只有连 https 私有 Manager 才用得上 |
| `verify` | `False` 关闭证书校验 |

先看看有什么：

```python
print(mgr.system_status())         # {'running_count': 1, 'binary_version': …}

for i in mgr.list_instances():
    print(i.uid, i.name, "running" if i.ready else "stopped", sorted(i.tags))
```

`list_instances()` 返回 `InstanceInfo`：

| 字段 | 含义 |
|---|---|
| `id` | profile 的 UUID |
| `provider` | 哪个 provider 报上来的 |
| `ready` | 是否 `status == "running"` |
| `name` | profile 名 |
| `tags` | `frozenset[str]`。Manager 存的是 `[{tag, color}]`，这里只取 `tag` |
| `uid` | `"{provider}:{id}"`，全局唯一，租约 key 的主体 |

随便租一个空闲的：

```python
with mgr.lease() as inst:
    print("租到了", inst.info.uid)
    with inst.session(human=True) as s:
        s.open("https://example.com")
```

> **token 不会进日志。** 所有异常消息和 `repr()` 都会走脱敏——`Endpoint.headers` 和
> `ws_url` 都是 `repr=False`，URL query 里的 token 只留头尾各 3 个字符。

### 5.3 指定某一个 profile 去发任务

参数是 `lease(instance_id=...)`，认的是 **profile 的 UUID**，不是名字。四种写法：

#### ① 已知 id

```python
with mgr.lease(instance_id="5edcc28a-8b31-4c9e-a1f0-77d2e6c04b19") as inst:
    with inst.session(human=True) as s:
        s.open("https://example.com")
```

裸 id 和 `"cloakbrowser:5edcc28a-…"` 这种 uid 形式都收。多 Manager 混池时用 uid 消歧。

#### ② 只知道名字

```python
with mgr.lease(name="Win-US-02") as inst:
    ...

with mgr.lease(names=["Win-US-02", "Win-US-03"]) as inst:   # 任意一个空的
    ...
```

> **0.4.0 起才有 `name=` / `names=`。** 0.3.x 要写 `where=lambda i: i.name == "..."`，
> 而且名字打错时会**阻塞到 timeout** 才抛 `TimeoutError` —— 现在是立刻 `NotFound`，
> 并把看得见的名字列出来。

#### ③ 按 tag 路由

```python
with mgr.lease(where=lambda i: "us" in i.tags) as inst:
    ...

# 组合条件
with mgr.lease(where=lambda i: "us" in i.tags and "banned" not in i.tags) as inst:
    ...
```

#### ④ 名字 → id，然后按 id 租

```python
raw = mgr.find_profile("Win-US-02")          # 原始 dict，找不到返回 None
if raw:
    with mgr.lease(instance_id=raw["id"]) as inst:
        ...
```

或者走幂等创建，顺手拿到 id（见 [5.4](#54-快速构建-profile以及怎么传参)）。

#### `lease()` 全部参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `where` | `None` | 作用在 `InstanceInfo` 上的谓词 |
| `name` | `None` | 按 `info.name` 精确匹配。与 `names` 互斥 |
| `names` | `None` | 按 `info.name` 匹配其中任意一个 |
| `instance_id` | `None` | 指定实例。裸 id 或 uid |
| `provider` | `None` | 只在这个 provider 里挑（多 Manager 场景） |
| `block` | `True` | `False` 表示拿不到立刻抛 `Busy` |
| `timeout` | `None` | 阻塞上限，秒。`None` 一直等，超时抛 `TimeoutError` |
| `ready_only` | `False` | `True` 跳过没在运行的实例 |

以上筛选条件之间是**与**关系。

#### 一次租一批：`lease_many(n, **kw)`

```python
from contextlib import ExitStack

with ExitStack() as stack:
    for inst in pool.lease_many(4, names=NAMES, timeout=60):
        stack.enter_context(inst)
        ...
```

**部分失败会整体回滚** —— 拿到 3 个第 4 个超时，那 3 个会被还回去再抛。自己写循环
最容易漏的就是这一步，漏了就是三个实例被白占一整个 TTL。

`timeout` 是**整批**的上限，不是每个的。

#### 三个必须知道的行为

**① profile 停着也能租。** 租到之后 Pool 会调 `ensure_ready()` 把它拉起来并等就绪
（默认最多 60 秒）。想只挑已经在跑的：

```python
with mgr.lease(instance_id=pid, ready_only=True) as inst:
    ...
```

**② 被别人占着时默认是阻塞等，不是立刻报错。**

```python
mgr.lease(instance_id=pid)                 # 一直等到它空出来
mgr.lease(instance_id=pid, timeout=30)     # 等 30 秒，然后抛 TimeoutError
mgr.lease(instance_id=pid, block=False)    # 立刻抛 Busy
```

**③ 匹配不上任何实例，抛 `NotFound`，而且是立刻。**「都被占着」和「根本没有这个
实例」是两回事：前者等下去有意义，后者等到天亮也没用。判定之前 Pool 会强制刷一次
发现缓存，所以刚建出来的 profile 不会被误判；报错里会列出**看得见**的实例名 ——
这类错九成是名字打错了。

例外是 `ready_only=True`：它筛的是**状态**不是身份，实例这会儿没起来不代表它不存在，
所以这一项仍然是阻塞等待。

#### 租约的边界：协作式排他，不是强制隔离

租约只能约束**通过 sleight 访问的客户端**。它拦不住：

- 通过 VNC 直接操作浏览器的人
- 不走 sleight、自己连 CDP 的其它程序
- Manager 自带的 Web UI

它防的是**你自己的多个任务互相踩**，不是入侵防护。

机制上：TTL 默认 30 秒，后台线程按 TTL/3 续租；续租失败会立刻标记 `lease_lost`
**并关闭 WebSocket**——连接关了就发不出命令，比检查标志位可靠。此后所有操作抛
`LeaseLost` 而不是 `ConnectionError`，因为前者绝不能重试，后者可以。

### 5.4 快速构建 profile，以及怎么传参

#### 最短路径

```python
from sleight.providers import CloakBrowserManager, ProfileSpec

mgr = CloakBrowserManager("http://127.0.0.1:19000", token="…")

spec = ProfileSpec.windows_us(                       # ① 挑一个自洽的底子
    "Win-US-02",
    proxy="socks5://user:pass@hk.example:3000",      # ② 传参就是关键字参数
    fingerprint_seed=20260729,
    tags=("us", "prod"),
)
info = mgr.ensure_profile(spec)                      # ③ 按 name 幂等
with mgr.lease(instance_id=info.id) as inst:         # ④ 租它
    with inst.session(human=True) as s:
        s.open("https://example.com")
```

不落盘、不写 YAML——`to_payload()` 直接构造 JSON body POST 给 `/api/profiles`。

#### 四个预设工厂

它们的价值不是省字数，是**保证指纹自洽**：平台、时区、语言、GPU 串锁成同一台机器上
真会出现的组合。`platform="windows"` 配一串 Apple Metal renderer 是一眼就会被标记的
矛盾。

| 工厂 | 锁定的组合 |
|---|---|
| `ProfileSpec.windows_us(name, **kw)` | `America/New_York` + `en-US` + Windows + NVIDIA RTX 3070 (D3D11) |
| `ProfileSpec.windows_hk(name, **kw)` | `Asia/Hong_Kong` + `zh-HK` + Windows + Intel UHD 630 |
| `ProfileSpec.macos_us(name, **kw)` | `America/Los_Angeles` + `en-US` + macOS + Apple M2 Metal |
| `ProfileSpec.linux_us(name, **kw)` | `America/New_York` + `en-US` + Linux + Mesa llvmpipe |

`**kw` 覆盖任何一项，但**只覆盖你真要改的**——覆盖 `gpu_renderer` 而不改 `platform`
会被 `validate()` 当场拒掉。

#### 组装过程：从零到能跑

上面那四行是结果，这里是过程。六步，每步都能单独停下来检查。

##### 第 1 步 · 选底子

**用预设**（推荐）。预设不是省字数，是把平台、时区、语言、GPU 串一次性锁成自洽的一组：

```python
from sleight.providers import ProfileSpec

spec = ProfileSpec.windows_us("Win-US-02")
```

这一行填出来的是：

```
platform     = 'windows'
timezone     = 'America/New_York'
locale       = 'en-US'
gpu_vendor   = 'Google Inc. (NVIDIA)'
gpu_renderer = 'ANGLE (NVIDIA, NVIDIA GeForce RTX 3070 (0x00002484) Direct3D11 vs_5_0 ps_5_0, D3D11)'
```

**或者从零手写**，一个字段都不预填 —— 没填的交给 Manager 用它自己的默认值：

```python
spec = ProfileSpec(
    name="Bare",
    platform="linux",
    timezone="Europe/Berlin",
    locale="de-DE",
)
```

代价是 GPU 串没人管了：Manager 会给一个它自己的默认值，你没法保证它和
`platform="linux"` 对得上。**自己填 GPU 串就得自己保证自洽**，`validate()` 只能拦住
明显的矛盾（Windows 配 Metal 那种），拦不住"Linux 配一块 Windows 上才有的显卡型号"。

`to_payload()` 只做三件事：

| 规则 | 例 |
|---|---|
| **`None` 的字段整个丢掉** | 上面没有 `user_agent` 和 `color_scheme` —— 它们是 `None` |
| `tags` 展开成 Manager 要的形状 | `("us", "prod")` → `[{"tag": "us"}, {"tag": "prod"}]` |
| `launch_args` 元组转 list | `()` → `[]` |

> **「丢掉 `None`」是最容易被误解的一条。** 它意味着 `user_agent=None` 不是"清空
> user_agent"，而是"这个字段我不管"。想把服务端已有的值真的抹掉，用 `CLEAR`：
>
> ```python
> from sleight.providers import CLEAR, UNSET
>
> ProfileSpec(name="x", user_agent=CLEAR)          # → payload 里 user_agent: ""
> mgr.update_profile(pid, user_agent=CLEAR)        # 真的清掉
> mgr.update_profile(pid, user_agent=UNSET)        # 什么也不做（等价于不写）
> ```
>
> **0.4.0 起裸空串会被拒绝。** `user_agent=""` 和 `user_agent=None` 只差一个字符、
> 做的却是相反的事，而从签名上一点都看不出来 —— 现在它直接 `ValueError` 并指向
> `CLEAR`。

对照一下 `geoip=True` 的模式，注意 `timezone` / `locale` **不在** payload 里：

##### 第 4 步 · 校验

```python
spec.validate()          # 通过则静默返回；有冲突抛 ValueError，逐条列出
```

什么时候自动跑：

| 入口 | 是否校验 |
|---|---|
| `ProfileSpec.windows_us(...)` 等四个预设工厂 | ✅ 当场 |
| `ProfileSpec(...)` 直接构造 | ❌ 不校验 |
| `spec.replace(...)` | ❌ 不校验 |
| `mgr.create_profile(spec)` | ✅ 下发前 |
| `mgr.ensure_profile(spec)` | ✅ 下发前 |

所以「直接构造 + 立刻下发」这条路照样是安全的，只是错误报得晚一点。手动调
`validate()` 的价值在批量场景 —— 一次性把 50 个 spec 全过一遍，别跑到第 37 个才炸：

```python
for spec in specs:
    spec.validate()       # 全部通过了再开始下发
for spec in specs:
    mgr.ensure_profile(spec)
```

##### 第 5 步 · 下发

两个入口，语义完全不同：

| | `create_profile(spec)` | `ensure_profile(spec)` |
|---|---|---|
| 同名已存在 | **再建一个**（Manager 允许重名） | 比对差异，只 PUT 变了的字段 |
| 不存在 | 创建 | 创建 |
| 重复运行脚本 | 每跑一次多一个 profile | 幂等 |
| 适合 | 明确要新建一份 | **绝大多数情况** |

```python
info = mgr.ensure_profile(spec)
print(info.id, info.name, info.tags)
```

`ensure_profile` 的差异比对有一个坑值得单独说：服务端存的 tags 是
`[{tag, color}]`，spec 给的是 `[{tag}]`，直接比字典永远不相等。所以 tags 是**按
归一化后的名字集合**比的 —— 改了 tag 重跑会真的发 PUT。这一点有回归测试盯着，
因为 tags 正是 Pool 的路由键（`where=lambda i: "us" in i.tags`），漏更新的话重新
打标的 profile 会继续被旧谓词选中。

##### 第 6 步 · 启动并验证指纹真的生效

`auto_launch` 默认 `False` —— 建 profile 和起浏览器是两件事，建完不该立刻占一份内存。
三种拉起方式：

```python
mgr.ensure_ready(info.id)                          # 显式拉起，幂等，已 running 就 no-op
mgr.create_profile(spec, launch=True)              # 建完立刻起
with mgr.lease(instance_id=info.id) as inst: ...   # 租的时候自动拉起（最常用）
```

**冷启动约 70 秒**（3.8 GB 内存的机器，含 Xvnc 拉起和写默认书签）。两个超时管的是
不同的东西，名字很像，别混：

| | 默认 | 管什么 | 调它的场景 |
|---|---|---|---|
| `mgr.lifecycle_timeout` | `300` s | `launch` / `stop` **这一条 HTTP 请求**能挂多久 | 机器很慢、profile 很大 |
| `mgr.ready_timeout` | `60` s | `ensure_ready()` **轮询 `status()` 等它变 running** 的总时限 | Manager 是异步返回的 |
| `mgr.ready_poll` | `0.5` s | 上面那个轮询的间隔 | 几乎不用调 |

Manager 的 `launch` 是**同步**的 —— 返回时实例已经起来了，所以 `ready_timeout` 的轮询
通常一圈就结束，真正在等的是 `lifecycle_timeout`。把它设成通用的 15 s 会在**浏览器
其实已经起来**的情况下抛 `ConnectionError`，而从那个异常里完全看不出实例到底起没起。

**组装完一定要验一次。** 配错的指纹不会报错，它只是安安静静地和你的预期不一样：

#### 六个坑

1. **`geoip=True` 不能同时手写 `timezone` / `locale`。** 两者会打架，`validate()`
   直接抛。预设工厂检测到 `geoip=True` 会自动跳过预填。`geoip` 没配 `proxy` 也会被拒
   ——没东西可推导。
2. **`humanize` / `human_preset` 对你没用。** 那是浏览器进程内部的拟人，外部 CDP
   客户端拿不到（实测 press 与 release 之间 0 条 move 事件）。拟人由 sleight 的
   `human=` 做。
3. **直接 `ProfileSpec(...)` 构造不校验。** 预设工厂当场校验，
   `create_profile` / `ensure_profile` 也校验。用 `replace()` 派生时校验推迟到下发。
4. **viewport ≠ screen_height。** Manager 实测差 133 px，用 `spec.viewport_height`
   拿准数（1080 → 947）。
5. **留 `None` 的字段不会下发。** `to_payload()` 丢掉 `None` 和 `UNSET`，所以
   `ensure_profile` 也不会把服务端已有的值改回默认。想真正清空某个字段用 `CLEAR`；
   裸空串会被 `validate()` 拒绝。
6. **罕见分辨率只 `warning` 不报错。** 罕见本身就是熵，可能是你故意的。

#### `validate()` 拦什么

| 冲突 | 处理 |
|---|---|
| `platform="windows"` + GPU 串含 Apple / Metal | `ValueError` |
| `platform="macos"` + GPU 串含 Direct3D / D3D11 | `ValueError` |
| `platform="linux"` + GPU 串含 Direct3D / Metal | `ValueError` |
| `geoip=True` 同时手写 `timezone` / `locale` | `ValueError` |
| `geoip=True` 但没配 `proxy` | `ValueError` |
| `user_agent` 声明的系统与 `platform` 不符 | `ValueError` |
| 分辨率不在常见列表里 | `UserWarning` |

### 5.5 多线程并发跑一批任务

**硬约束：`max_workers` ≤ 实例数。** 一个实例同时只给一个 Session，多了只会在
`lease()` 上排队，不会更快。

```python
from concurrent.futures import ThreadPoolExecutor
from sleight.providers import CloakBrowserManager

mgr = CloakBrowserManager("http://127.0.0.1:19000", token="…")

def fetch(url: str) -> str:
    with mgr.lease(timeout=300) as inst:        # 阻塞直到拿到空闲实例
        with inst.session(human=True) as s:
            s.open(url)
            return s.content()

with ThreadPoolExecutor(max_workers=3) as ex:   # 3 个实例 → 3 个 worker
    results = list(ex.map(fetch, urls))
```

`mgr.lease()` 之所以线程安全，是因为 `mgr.pool` 是**懒创建的单例**——所有线程共享
同一份锁表。这是这个库最重要的一条不变量，`tests/test_lease_exclusivity.py` 用
20 线程抢 3 实例把它锁死。

#### 传任务参数

没有专门机制，就是普通的 Python 函数参数：

```python
def run(url: str, keyword: str) -> list[str]:
    with mgr.lease(where=lambda i: "us" in i.tags) as inst:
        with inst.session(human=True) as s:
            s.open(url)
            s.type("#q", keyword, clear=True)
            s.press("Enter")
            s.wait(Selector(".result"), timeout=20)
            return [e.text() for e in s.query_all(".result h3")]
```

#### 一个任务里开多个 tab

同一个实例上可以有多个 Session，但**不要并发操作它们**——`Session` 不是线程安全的，
`Transport` 会直接拒绝跨线程调用。

```python
with mgr.lease() as inst:
    a = inst.session(human=True)
    b = inst.session(human=True)
    try:
        a.open("https://example.com/1")     # 串行，不要放进两个线程
        b.open("https://example.com/2")
    finally:
        a.close()
        b.close()
```

handle 关闭时会强制关掉所有还开着的 Session 并记一条 warning。想让这种情况直接报错，
用 `Pool(providers, strict_close=True)`。

#### 并发契约：谁能跨线程，谁不能

一句话：**`Transport` 归属创建它的那个线程，`Pool` / 锁表是共享的。**

| 对象 | 跨线程 | 违反时会怎样 |
|---|---|---|
| `Pool` / `mgr.lease()` / 锁表 | ✅ **就该共享** | —— |
| `Provider`（`mgr` 本身） | ✅ | —— |
| `InstanceHandle` | ❌ 一个线程一个 | 它底下是一条 `Transport` |
| `Session` | ❌ | 同上 |
| `Transport` | ❌ **会当场拒绝** | `RuntimeError`，消息里带创建线程和调用线程的 id |
| `HumanProfile` / `ProfileSpec` / `DeploySpec` | ✅ frozen | —— |

`Transport` 记住创建它的线程 id，每次发命令都核对一次。**这是刻意的**：CDP 是单条
WebSocket 上的请求-响应复用，两个线程同时读同一个 socket 会互相吃掉对方的响应 ——
表现是随机的超时和张冠李戴的返回值，比直接报错难查一个数量级。

所以正确的并发形状只有一种：**每个线程 `lease()` 自己的实例，在自己的线程里建
`Session`**，就是上面 `ThreadPoolExecutor` 那段。别把一个 handle 传进线程池。

```python
# ❌ 会抛 RuntimeError
with mgr.lease() as inst, inst.session() as s:
    with ThreadPoolExecutor(4) as ex:
        ex.map(lambda u: s.open(u), urls)      # s 属于主线程

# ✅
def one(url):
    with mgr.lease() as inst, inst.session() as s:   # 每个线程自己租、自己建
        s.open(url)
        return s.content()

with ThreadPoolExecutor(3) as ex:
    results = list(ex.map(one, urls))
```

后台续租线程是唯一的例外，它不碰 `Transport` —— 它只调 `lease.renew()`，而锁表后端
（`MemoryLease` / `RedisLease`）本来就是线程安全的。续租失败时它调 `handle._sever()`
**关闭** socket（这是安全的，关闭不是发命令），于是 owner 线程下一次操作拿到的是
`LeaseLost` 而不是一个和隧道抖动分不清的 `ConnectionError`。

#### 多进程 / 多机

进程内的 `MemoryLease` 不跨进程。触发条件是**有几个进程**，不是有几个实例：

| 场景 | 后端 |
|---|---|
| 单进程串行 | 不用（或 `memory`，零成本） |
| 单进程多线程并发 | `memory`（默认） |
| 单进程跨 3 个 Manager 共 30 个实例 | `memory` |
| **多进程 / 多机共享同一批实例** | `redis` |
| 多进程但每进程静态绑死一个 uid | 不用（代价：崩溃后无法互相接管） |

跨进程用内置的 `RedisLease`（`0.1.4` 起）：

```bash
pip install "sleight[redis]"
```

```python
from sleight import Pool
from sleight.lease import RedisLease

pool = Pool(
    providers,
    lease=RedisLease("redis://127.0.0.1:6379/0"),
    namespace="prod",
)
```

| 参数 | 说明 |
|---|---|
| `url` | 连接串，如 `redis://:pw@host:6379/0`。与 `client` 二选一 |
| `client` | 已有的 redis 客户端（想共用连接池时给这个）。与 `url` 二选一 |
| `prefix` | Redis key 前缀，默认 `"sleight"` |

`prefix` 和 `Pool` 的 `namespace` 是两件事：前者把 sleight 的锁和同一个库里的其它
数据分开，后者区分环境。最终 key 形如 `sleight:prod:cloakbrowser:5edcc28a`。

诊断用 `store.held_keys()`（走 `SCAN`，不是会阻塞整个 Redis 的 `KEYS`）。

**`renew` 和 `release` 都走 Lua CAS**（`GET == token` 才动手），而且必须在 Redis 侧
原子完成。客户端先 `GET` 再 `DEL` 中间有窗口：`GET` 通过之后锁可能刚好过期并被别人
抢走，然后你把**他的**锁删了 —— 那正是租约要防的事。

**过期的租约续不回来**，哪怕还没被别人抢走：key 到点就被 Redis 自己删了。
`MemoryLease` 特意实现了同样的语义，免得同一段"进程卡顿了一下"的代码在两个后端上
结果相反 —— 一个悄悄续上继续发 CDP 命令，一个抛 `LeaseLost`。

要换别的后端（etcd、Consul、数据库行锁）也容易，`Lease` 协议只有三个方法：

```python
class Lease(Protocol):
    def acquire(self, key: str, *, ttl: float) -> str | None: ...   # 返回 owner_token
    def renew(self, key: str, token: str, *, ttl: float) -> bool: ...
    def release(self, key: str, token: str) -> None: ...
```

### 5.6 拟人档位怎么选

#### 三层控制

```python
inst.session()                       # 默认 human=False，全部直通
inst.session(human=True)             # 默认全部拟人，用 DEFAULT 预设
inst.session(human=CAREFUL)          # 默认拟人且用 CAREFUL 预设

s.click(el)                          # 跟随 Session 默认
s.click(el, human=True)              # 单句开启
s.click(el, human=False)             # 单句关闭，抢时间
s.click(el, human=DEFAULT.replace(overshoot=0))   # 单句微调
```

规则：`None` → 继承 Session 默认；`False` → 直通；`True` → Session 默认预设
（未指定则 `DEFAULT`）；`HumanProfile` 实例 → 用它。

#### 三档预设

```python
from sleight import FAST, DEFAULT, CAREFUL
```

| | `FAST` | `DEFAULT` | `CAREFUL` |
|---|---|---|---|
| 用途 | 抢时间，低风险页面 | 日常 | 高风险页面：慢、抖、犹豫 |
| 弓形 `bow` | 0.10 | 0.18 | 0.26 |
| Fitts 斜率 `fitts_b` | 0.05 s/bit | 0.10 | 0.16 |
| overshoot 幅度 | 0.3 | 1.0 | 1.4 |
| 打字均值倍数 | 0.70 | 1.0 | 1.35 |
| 打字方差倍数 | 0.60 | 1.0 | 1.30 |
| 同一段 749 px 移动的点数 | 31 | 38 | 48 |

**点数是单调的**（FAST < DEFAULT < CAREFUL），这一点很重要：如果靠拉长 `step_delay`
来"变慢"，会得到一个反直觉的结果——谨慎模式发出的事件反而**更少**，轨迹更粗糙、
更容易被识别，而快速模式还更费带宽。快慢由 `fitts_b` 的时长控制。

#### 自定义

```python
from sleight import HumanProfile, DEFAULT

MY = DEFAULT.replace(
    fitts_b=0.13,              # 慢一点
    overshoot=0.0,             # 关掉冲过头
    think_every=(4, 9),        # 打字时更频繁地停顿思考
)

with inst.session(human=MY) as s:
    ...
```

主要字段：

| 字段 | 默认 | 含义 |
|---|---|---|
| `step_delay` | `(0.008, 0.020)` | 每个轨迹点后的停顿 = 鼠标**回报率**（50–125 Hz）。**不要用它调快慢** |
| `wind` | `3.0` | 手抖幅度。0 = 纯贝塞尔，没有抖动 |
| `bow` | `0.18` | 贝塞尔弓形，占路径长度的比例。0 = 直线 |
| `max_points` | `220` | 点数上限。跨屏拖拽不该发上千个事件 |
| `fitts_a` / `fitts_b` | `0.10` / `0.10` | Fitts 定律的截距（秒）与斜率（秒/bit） |
| `overshoot` | `1.0` | 冲过头的幅度系数。0 = 关闭 |
| `overshoot_threshold` | `500.0` | px。短距离不冲过头 |
| `overshoot_ramp` | `0.5` | 概率渐变区间，按阈值的倍数算。**不要设成 0** |
| `reaction` | `(0.060, 0.180)` | 到位后按下前的反应时间 |
| `dwell` | `(0.060, 0.150)` | 鼠标按压时长 |
| `inter_click` | `(0.040, 0.120)` | 双击的两下之间 |
| `drag_settle` | `(0.080, 0.240)` | 拖到位之后、松手之前的迟滞。见 [5.10](#510-拖拽滑块与看板卡片) |
| `drag_overshoot_threshold` | `60.0` | px。拖拽单列的过冲阈值 —— 滑块只有一两百像素宽 |
| `key_dwell` | `(0.060, 0.120)` | 按键按下到抬起 |
| `typing_scale` / `typing_spread` | `1.0` / `1.0` | 击键间隔的均值 / 方差倍数 |
| `think_every` | `(8, 15)` | 平均每几个字符插一次思考停顿 |
| `think_pause` | `(0.20, 0.60)` | 思考停顿时长 |
| `landing_sigma` | `0.25` | 落点高斯的标准差，相对 box 半宽 |
| `edge_inset` | `3` | 落点内缩像素，会按元素尺寸自适应收窄 |
| `scroll_step` | `(80, 160)` | 单次 `mouseWheel` 的 deltaY |

#### 拟人到底做了什么

| 要素 | sleight | 反面教材 |
|---|---|---|
| 落点 | bbox 内截断高斯，自适应内缩 | 恒定点正中心 |
| 坐标 | 整数 | 用小数位当"抖动" |
| 轨迹 | 三阶贝塞尔，控制点单侧随机偏移，按弧长重参数化 | 直线插值 |
| 抖动 | WindMouse 风力项（相关噪声，lag-1 自相关 ≈ 0.72） | 无，或每点独立高斯（白噪声） |
| 速度 | 加速 → 巡航 → 减速 | 匀速 |
| 点数 | Fitts 定律，随距离/目标大小变 | 固定 `steps=N` |
| 步进间隔 | 8~20 ms，非固定 | 固定 sleep |
| overshoot | 超阈值后概率渐变触发，幅度随距离缩放 | 精确到达 / 每次都冲 |
| 前置停顿 | 到位后 60~180 ms 再按下 | 立刻按 |
| 按压时长 | 60~150 ms | 0 ms |
| 起点连续 | 维护当前鼠标位置 | 每次都从 (0,0) |
| 打字 | 逐字符 keyDown/keyUp，按 digraph 取间隔 | 一次 `insertText` |
| 双击 | 两次完整按下抬起，`detail` 依次 1、2 | `clickCount=2` 塞进单次 press |
| 滚动 | 多次小步 `mouseWheel` | 一次 `scrollTo` |

**关于中文输入的如实声明**：非 ASCII 走 `Input.insertText`，它**不产生**
`compositionstart` / `compositionupdate` / `compositionend`。真实 IME 输入会产生这三个
事件，认真做行为检测的站点能区分。说它"更接近真人中文输入"是过度声称——这是权衡之后
的选择（逐键 keydown 打中文更不真实），不是完美方案。

### 5.7 等待、超时与元素找不到

#### 六种等待条件

```python
from sleight import DomReady, Load, Text, Selector, Gone, NetworkIdle
```

| 条件 | 实现 | 什么时候用 |
|---|---|---|
| `DomReady()` | 订阅 `Page.lifecycleEvent` 的 `DOMContentLoaded` | 默认，够用 |
| `Load()` | 同上，等 `load` | 需要图片/子资源都到位 |
| `Text("Sign in")` | 轮询 `document.body.innerText` 包含子串 | 最直观，前端框架渲染完才出现的文案 |
| `Selector("#app")` | 轮询选择器命中数 > 0 | 等某个元素出现 |
| `Gone(".spinner")` | 轮询选择器命中数 == 0 | 等 loading 消失 |
| `NetworkIdle(quiet=0.5)` | 在飞请求集合为空后再静默 `quiet` 秒 | XHR 密集的页面 |

```python
s.open("https://example.com", wait=Text("Sign in"))
s.wait(Gone(".spinner"), timeout=20)
s.wait(NetworkIdle(quiet=1.0), timeout=30)
```

一次只收一个条件，要复合就连着调两次。

#### 三条语义上的坑

**① `NetworkIdle` 不等于"页面全部加载完"。** 它的语义是**「attach 之后发起的请求都
结束了」**——attach 之前已经在飞的请求 sleight 看不到。

长连接（WebSocket / EventSource）和分块流式响应（长轮询、SSE-over-fetch、gRPC-web）
永远不结束，会被主动排除；此外还有一条按年龄剔除的兜底（在飞超过 15 秒视为流）。

**② 同文档导航不产生任何 lifecycle 事件。** hash 路由（`#section`）的
`Page.navigate` 不返回 `loaderId`。sleight 检测到这种情况会让 `DomReady` / `Load`
直接返回，其余条件照常轮询。

**③ 超时异常带着最后一次求值结果。**

```python
from sleight.core.errors import TimeoutError

try:
    s.wait(Selector("#app"), timeout=10)
except TimeoutError as e:
    print(e)                 # timed out after 10s waiting for Selector('#app')
    print(e.last_value)      # 0 —— 最后一次数出来几个
```

#### 元素定位

```python
el = s.query("#login")             # 第一个，没命中返回 None
els = s.query_all("li.item")       # 全部，没命中返回空列表

el.box()                           # Box | None，viewport CSS 像素
el.require_box()                   # 拿不到就抛 ElementError
el.text()                          # innerText
el.attr("href")                    # HTML **属性**
el.value()                         # 表单控件的当前值（DOM **property**）
el.select_option(value=…/label=…)  # 同 s.select_option
el.upload_file(path, …)            # 同 s.upload_file
el.screenshot("captcha.png")       # 只截这一个元素
el.in_viewport()                   # 现在能看见吗
el.hit_test(x, y)                  # 这个点最上层的是不是它
```

> ⚠️ **`attr("value")` 不是 `value()`。** 前者是 HTML 里写死的那个初值，**不随用户
> 输入变化**；校验"刚才 `type()` 进去的内容对不对"必须用后者。

**作用域限制：只支持主 frame 的普通 DOM。** 不支持 iframe / OOPIF，不穿透 Shadow DOM。
需要这些用 Playwright。

#### 命中校验

每次 `click()` 都会做**两次**命中校验——取到几何时一次、轨迹跑完时一次。轨迹要跑
300 ms 到 2 s，这期间 cookie 横幅、懒加载的 sticky 头部、模态框都可能冒出来盖住目标。
只查一次等于没查。

被遮挡时抛的 `ElementError` 会点名挡住它的元素：

```
<Element '#submit'> is covered at (412, 680) after the pointer arrived;
topmost element is <div#cookie-banner.fixed.bottom-0>
```

多数库不做这步，症状是"点了但没反应"，排查极费时间。

#### `clear=True` 之前会检查焦点

点击只保证**几何命中**，不保证元素可聚焦——点一个 `<div>` 焦点会留在原处，于是
`Ctrl+A` + `Backspace` 清空的是**别的**输入框。`type(clear=True)` 会先确认
`document.activeElement` 真的落在目标上，不对就抛 `ElementError`。

### 5.8 多个 Manager 聚合成一个池

```python
from sleight import Pool
from sleight.providers import CloakBrowserManager, Plain

pool = Pool(
    [
        CloakBrowserManager("http://10.0.0.1:9000", token=T1, name="hk"),
        CloakBrowserManager("http://10.0.0.2:9000", token=T2, name="sg"),
        Plain("http://127.0.0.1:9222", name="local"),
    ],
    namespace="prod",          # 租约 key 前缀，隔离多套环境
    ttl=30.0,                  # 租约存活秒数
    discovery_ttl=5.0,         # list_instances() 的缓存秒数
)

with pool.lease() as inst:
    print(inst.info.uid)                       # "hk:5edcc28a-…"

with pool.lease(where=lambda i: "us" in i.tags) as inst:
    ...

with pool.lease(provider="sg") as inst:        # 只在新加坡那台上挑
    ...
```

Provider 的 `name` 在池内**必须唯一**，`Pool.__init__` 直接拒绝重复——uid 靠它保证
全局唯一。

#### Pool 的行为

| 问题 | 行为 |
|---|---|
| 发现开销 | `list_instances()` **并发**拉取 + TTL 缓存（默认 5 秒） |
| 慢 / 挂掉的 Manager | 单 provider 超时或抛异常 → 本轮跳过 + warning，**不阻塞全池**；连续失败进指数 backoff（上限 60 秒） |
| 选择策略 | first-free，但按 provider **打散起始下标**，否则总把第一个 Manager 塞满 |
| 未就绪的实例 | 默认参与调度，租到后 `ensure_ready()` 拉起；`ready_only=True` 可关 |
| 跨 Manager 迁移任务 | **不做**。租到哪个就在哪个跑完 |

**Pool 不做**负载权重、地域路由、健康评分。这些用 `where=` 表达，塞进 Pool 就会长成
调度器。

#### 不要自己做 round-robin

任务耗时不均是常态，轮询会把新任务硬塞给正忙的实例排队；`lease()` 的 first-free
天然是 work-stealing。「按 provider 打散」只作用于**平级空闲实例的起始顺序**，
不改变 first-free 语义。

### 5.9 抓页面加载了哪些 JS / CSS / XHR

`session.capture_resources()` 把 `Network.*` 事件攒成结构化的资源清单。
**库不负责打印** —— 筛选和输出格式由你决定。

```python
from sleight import Load, NetworkResource

def print_resource(resource: NetworkResource) -> None:
    label = {"Script": "js", "Stylesheet": "css"}.get(resource.resource_type)
    if label:
        print(f"[{label}] {resource.url}")

with mgr.lease(name=PROFILE_NAME, timeout=60) as inst:
    with inst.session() as s:
        with s.capture_resources(
            types={"Script", "Stylesheet"},
            dedupe_by="url",
            on_discovered=print_resource,
        ) as capture:
            s.open(TARGET_URL, wait=Load(), timeout=90)
            s.pump_events(duration=10)        # load 之后还有一批异步拉的

        print(f"js={len(capture.urls('Script'))} css={len(capture.urls('Stylesheet'))}")
```

#### `capture_resources()` 的参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `types` | `None`（全要） | CDP `ResourceType` 集合。**拼错会直接抛 `ValueError`** —— 写成 `"StyleSheet"` 的后果本来是静默抓不到任何东西 |
| `predicate` | `None` | 自定义谓词，与 `types` 是**与**关系，如 `lambda r: r.status == 200` |
| `dedupe_by` | `"url"` | 每个地址只报一次。`"request_id"` 每条请求一次，`None` 不去重 |
| `on_discovered` | `None` | 资源**首次满足筛选条件**时回调 |

常用的 `ResourceType`：`Document` `Script` `Stylesheet` `Image` `Font` `Media`
`XHR` `Fetch` `WebSocket` `EventSource` `Manifest` `Ping` `Other`。

#### `NetworkResource` 有什么

| 字段 | 说明 |
|---|---|
| `url` | 有重定向时是**最后**那一跳 |
| `resource_type` | 响应还没回来时可能是空串 |
| `request_id` | 重定向复用同一个 id |
| `method` / `mime_type` / `status` | |
| `from_cache` | 命中磁盘或内存缓存 |
| `finished` / `failed` / `error_text` | 失败的请求也会保留，`error_text` 如 `net::ERR_BLOCKED_BY_CLIENT` |
| `size` | 传输字节数，未完成时 `None` |
| `redirects` | 这条链上被重定向掉的历史 URL |
| `pending` | 既没成功也没失败 |

取结果：`capture.snapshot()`（按发现顺序，是快照不是视图）、`capture.urls("Script")`、
`capture.by_type()`、`len(capture)`。

#### 三个必须知道的语义

**① 回调时机是"首次满足筛选"，不是"首次看见"。** `requestWillBeSent` 上的 `type`
经常缺失，只有 `responseReceived` 带的才权威。如果你自己在 `requestWillBeSent`
那一刻判断类型，这些资源会被整个漏掉。

**② 重定向链是一个资源。** CDP 的重定向复用同一个 `requestId`，`url` 指向最终那一跳，
中间跳进 `redirects`。手写实现最容易把 302 的地址当成结果。

**③ 看不到 attach 之前就发起的请求。** 和 `NetworkIdle` 是同一个语义边界。要抓完整的
首屏，`capture_resources()` 必须包住 `open()`。

#### 只关心失败的请求

```python
with s.capture_resources(predicate=lambda r: r.failed) as broken:
    s.open(url, wait=Load())
    s.pump_events(5)

for r in broken.snapshot():
    print(r.status, r.error_text, r.url)
```

#### 更底层：原始事件

`capture_resources()` 覆盖不到的事件（console、WebSocket 帧、`Page.*`）用
`observe_events()`。**不要去 monkeypatch `session._handle`** —— 那是私有方法，
而且多个补丁之间会互相覆盖。

```python
def log_console(ev):
    if ev.method == "Runtime.consoleAPICalled":
        print(ev.params.get("type"), ev.params.get("args"))

with s.observe_events(log_console):
    s.call("Runtime.enable")
    s.open(url, wait=Load())
    s.pump_events(5)
```

观察者在 Session 自己的状态机（导航纪元、网络空闲）**之后**被调用，只收本会话的事件。
它抛异常只会记一条 warning，不会打断事件流 —— 否则一个坏回调就能让所有 `wait()`
永远超时。

#### `pump_events()` 和 `wait()` 怎么选

| | 用什么 |
|---|---|
| 有明确条件（元素出现、文本出现、网络空闲） | `wait(Selector(...))` / `wait(NetworkIdle())` |
| 就是想再多收一会儿事件 | `pump_events(10)` |
| 想让浏览器停一会儿再动 | 都不是 —— 那是拟人节奏，`human=` 已经在做 |

`pump_events()` 不判断任何条件，纯粹是"原地收 N 秒"。有条件可判时别用它睡固定时长。

### 5.10 拖拽：滑块与看板卡片

**网页上的"拖"有两套互不相通的实现，先分清楚是哪一套。**

| | 靠什么驱动 | 典型场景 |
|---|---|---|
| JS 拖动 | 页面自己监听 `mousedown` / `mousemove` / `mouseup` | 滑块验证码、画布、地图平移、自制排序 |
| HTML5 原生拖放 | **浏览器自己的**拖拽控制器，页面只收 `dragstart` / `dragover` / `drop` | `draggable="true"` 的看板卡片、文件区 |

```python
s.drag("#slider-knob", by=(212, 0))        # 纯鼠标。滑块、画布、地图
s.drag_and_drop("#card", "#done-column")   # 看板卡片这类原生拖放
```

**两个都发 `button="left"`，所以两种实现其实都能被驱动。** 但对原生拖放，
`drag_and_drop()` 是**确定性**的那条路：它打开 `Input.setInterceptDrags`，按下、走出
几像素，然后看浏览器表态 —— 抛了 `Input.dragIntercepted` 就接管，把剩下的轨迹翻译成
`dragEnter` / `dragOver` / `drop`；没抛就继续发鼠标事件。`drag()` 则是把这件事交给
浏览器内部那个异步拖拽循环，时序上不由我们控制。想强制断言用 `native=True` /
`native=False`。

> **`button` 这个字段是硬要求。** 只给 `buttons` 位掩码的话，JS 滑块照常工作（它读的
> 就是 `e.buttons`），而 HTML5 原生拖放**一声不吭地不启动** —— `dragstart` 不触发、
> `Input.dragIntercepted` 永远不来，表现是"一切正常但什么也没发生"。Chrome 146 上
> 实测过：同一段轨迹，加上 `button="left"` 才有 `dragstart`。库里已经带上了，这条
> 记在这里是因为自己写 CDP 时极容易漏。

#### 滑块验证码

```python
knob  = s.require("#captcha-knob")
track = s.require("#captcha-track")
distance = track.require_box().w - knob.require_box().w

s.drag(knob, by=(distance, 0), human=CAREFUL)
```

拖拽段和普通移动有三处不同，都是风控在看的：

* **`buttons` 位掩码全程非零。** 掩码回 0 的移动就是 hover，页面一句 `e.buttons` 就
  知道键根本没按着；
* **过冲阈值单列**（`drag_overshoot_threshold`，默认 60 px）。指针移动那档是 500 px，
  滑块总共才一两百像素宽，套过去等于永不过冲 —— 而一条严格单调、终点恰好就是极值的
  轨迹，在滑块场景里本身就是异常值；
* **松手前有迟滞**（`drag_settle`，默认 80–240 ms）。**到位即松手**是机器最稳定的
  特征之一。

要更慢更犹豫就换 `CAREFUL`，或者自己调：

```python
from sleight import DEFAULT
profile = DEFAULT.replace(drag_settle=(0.25, 0.60), drag_overshoot_threshold=40.0)
```

#### 两端都得在视口里

按下之后 sleight **不会**滚页面 —— 滚动会让已经抓在手里的 box 失效，也没法还原成一次
连贯的人类动作。终点不在视口里会直接报 `ElementError`，先自己滚：

```python
s.scroll_into_view("#done-column")
s.drag_and_drop("#card", "#done-column")
```

#### 终点不做命中校验

起点会查两次（取到几何时、轨迹跑完时），和 `click()` 一样。终点**不查** —— 拖拽中的
实现普遍把被拖元素挂在光标底下（原生的 drag image、或 `position:fixed` 的克隆），
`elementFromPoint` 拿到的是它而不是放置区，查了只会对正确的拖拽误报。

### 5.11 甩掉站点的追踪 cookie

DataDome / PerimeterX 这类反检测服务会在浏览器里落一个设备标识（`datadome` 一类的
cookie）。要重新开始，得清掉它。

```python
from sleight import StorageType

report = s.clear_site_data("https://www.example.com")
if "datadome" not in (report.cookies or ()):
    log.warning("datadome 没清掉：%s", report)
```

#### 三个默认值，每个都有原因

**① 按 origin 收敛，不做全局清理。** `Network.clearBrowserCookies` 会把
bypass-paywalls 这类插件依赖的**其它站点**登录态一起端掉。要全清是显式动作：

```python
s.clear_browser_data()            # ⚠️ 所有站点的登录态都会掉
```

**② 默认清的不止 cookie。** 只清 cookie 会被 `localStorage` / `indexedDB` 里的副本
立刻还原 —— 反检测服务的设备标识不只落在 cookie 上。默认这五类：

`cookies` · `local_storage` · `indexeddb` · `cache_storage` · `service_workers`

要收窄就显式给：

```python
s.clear_site_data(origin, types=[StorageType.COOKIES])
```

**③ 类型是枚举，不是裸字符串。** CDP 那边收的是逗号分隔的字符串，拼错一个词
（`localstorage` 少个下划线）**不报错也不生效** —— 你以为清干净了，其实什么都没动。
枚举把这个变成 `ValueError`。

#### 返回值：到底清掉了什么

CDP 的清理命令**什么都不返回**，所以 `clear_site_data()` 自己前后各测一次：

```python
report = s.clear_site_data(origin)
report.cookies        # ('datadome', 'session') —— 真的消失的那些
report.usage_before   # 4096
report.usage_after    # 0
bool(report)          # 有没有真的清掉东西
```

`report.cookies is None` 表示**没测量**（构造 Session 时 `track_network=False`），
和 `()`「一个都没有」是两回事 —— 后者会让人以为清干净了。

#### 查某个 origin 有哪些 cookie，不用先导航过去

```python
s.cookies(urls=["https://www.example.com"])
```

### 5.12 换出口 IP：浏览器上下文

**症状**：走隧道采集，头十几篇正常，二三十篇之后开始出验证码 / 403。查出口 IP，
发现整轮都是同一个。

**原因**：隧道**按 TCP 连接**分配出口 IP，而 Chrome 会复用 keep-alive 连接。同一个
浏览器进程里的所有 tab 共用一个 socket pool，于是"换一个 tab""换一篇文章"根本不换连接，
也就不换出口。

#### 先确认症状：`exit_ip()`

```python
with inst.session() as s:
    print(s.exit_ip())          # 203.0.113.7

print(inst.exit_ip())           # 等价，自己开一个临时 tab 去问
```

请求从**页面里**发出去，走的就是浏览器的 socket pool 和代理 —— 这正是要测的东西。
两个坑库里已经躲开了：只用**纯文本端点**（拿 IP 查询站的首页去 `innerText` 里挑，
第一个 IP 未必是出口地址，一组实验会因此被读成无效结论），以及用 `ipaddress`
校验而**不手写正则**（页面上的 `12:34:56` 能匹配大多数 IPv6 正则，`2026.08.06`
能匹配 IPv4 正则）。

页面的 CSP 可能挡掉这个 fetch —— 在 `about:blank` 上调最稳，`inst.exit_ip()` 就是。

#### 试过什么、为什么不管用

| 手段 | 结果 | 为什么 |
|---|---|---|
| 清缓存 / 清 cookie | 无效 | 动的是存储，socket pool 归属不变 |
| URL 挂唯一查询参数 | 无效 | 只改 URL，连接照样复用 |
| 拉长请求间隔（2 s / 5 s） | 无效 | 不是空闲超时的问题 |
| `Network.emulateNetworkConditions` 切 offline 再切回 | **无效** | 它只作用在**渲染器**层面，动不了浏览器级的 socket pool。这条最反直觉，多数人会先想到它 |
| 换 HTTP 代理地址 | 视上游而定 | 上游要额外认证时方案本身不成立 |
| **新建 browser context** | **有效** | 独立网络栈、独立 socket pool，到隧道的连接**必然重建** |

#### 唯一有效的做法

```python
with mgr.lease(instance_id=info.id) as inst:
    for url in urls:
        with inst.context() as ctx, ctx.session(human=True) as s:
            s.open(url)
            ...            # 这一篇走的是一个新的出口
```

实测 10 篇 10 个不同出口。**不需要**给 context 单独指定 `proxy` —— 不传就继承进程级的
`--proxy-server`，而换出口靠的是新建 socket pool，不是换代理地址。

自己验一遍：

```python
seen = set()
for _ in range(5):
    with inst.context() as ctx:          # 别漏了 with —— 不然攒 5 个孤儿 context
        seen.add(ctx.exit_ip())
print(seen)                              # 应该是 5 个不同的
```

#### 资源清理必须由库兜住

手写要三步：断会话 → `Target.closeTarget` → `Target.disposeBrowserContext`，而且每步
都得独立 `try`。漏任何一步都会在浏览器里攒孤儿 target / context，而攒出来的东西在下一次
`Target.getTargets` 之前完全看不见。`with inst.context()` 就是为这件事存在的：

* 退出 `with` 时按序清理，每步独立 `try`，最后汇总成 `ExceptionGroup`；
* 忘了写 `with`，`inst.close()` 也会兜底；
* `dispose_on_detach=True`（默认）是第三道保险 —— 进程被 `kill -9` 时 `close()` 根本
  没机会跑，这时候由浏览器自己在连接断开后销毁。

#### ⚠️ 上下文里**用不了扩展**

实测结论，不是推测。同一个 profile、同一个扩展、同一个 URL，只换 context：

| | `chrome-extension://<id>/manifest.json` |
|---|---|
| 默认 context | 正常打开 |
| `inst.context()` 新建的 context | `net::ERR_BLOCKED_BY_CLIENT` |

原因：`Target.createBrowserContext` 建出来的是 **off-the-record**（无痕）上下文，而
Chrome 默认**不在无痕里启用扩展** —— 得用户在 `chrome://extensions` 上逐个勾"允许在
无痕模式下运行"，命令行装的扩展没有这个开关。

所以这两件事目前是**互斥**的：

* 要换出口 → 用 context → 扩展没了；
* 要扩展（付费墙解锁一类）→ 待在默认 context → 整轮一个出口。

依赖插件的采集**不能**照抄上面那个换出口的写法。可行的替代是**一个实例一个出口**：
多开几个 profile，每个配不同的上游代理，靠 `lease()` 轮换，而不是靠 context。

> 测试条件：Chrome 146 + 一个 MV3 扩展。换个 Chromium 分支或给扩展加
> `"incognito": "spanning"` 结果可能不同 —— 上量之前用上面那两行自己复现一遍。

#### 什么时候**不要**用它

上下文是**可选维度，不是替代实例的新粒度**。它省的是进程，不省内存 —— 每个 context
仍然要开渲染器进程、跑自己的那份 JS。需要不同指纹时，要的是不同 profile，不是不同
context：指纹是进程级的，一个实例里的所有 context 共用同一套。

### 5.13 少下点东西：屏蔽图片、广告、字体

正文采集不需要图片、广告、字体、媒体。走计费住宅代理时这直接是省钱，而且页面加载
更快、超时更少。

```python
with s.block(types=["Image", "Media", "Font"]) as blocked:
    s.open(url, wait=Load())

print(blocked.by_type)      # {'Image': 34, 'Font': 6}
print(blocked.allowed)      # 放行了多少条
```

按 URL 屏蔽，两者是**或**关系：

```python
with s.block(types=["Image"], url_patterns=["*://ads.*", "*doubleclick*"]):
    ...
```

`types` 收的是 CDP `ResourceType`（`Image` / `Media` / `Font` / `Stylesheet` /
`Script` / `XHR` / `Document` …），**大小写敏感**。写错了直接 `ValueError` ——
静默什么都不拦比报错难查得多。

> ⚠️ **只在 sleight 正在跟浏览器说话的时候生效。** 被暂停的请求要靠事件泵才能拿到
> 裁决，而事件泵跑在 `open()` / `wait()` / `pump_events()` 和每一次 `call()` 里。
> 纯 Python 的 `time.sleep()` 期间，页面发起的请求会挂着不动。要等就用
> `s.pump_events(n)`，别用 `time.sleep(n)`。

退出 `with` 时会 `Fetch.disable`，还挂着的请求全部放行 —— 中途抛异常也不会把页面卡死。

### 5.14 表单、刷新、视口

#### 下拉框：`select_option`

```python
s.select_option("#country", value="HK")
s.select_option("#country", label="中国香港")     # 按显示文本，去空白后精确匹配
```

**这是少数几个必须用 JS 的地方。** 原生 `<select>` 展开的是**操作系统的**弹出列表，
它根本不在页面里，鼠标事件够不着。

但也**不能只改 `el.value`** —— 那样页面的 `change` handler 一个都不会跑：联动的二级
下拉不刷新、表单校验不触发，而页面看上去是对的。`select_option()` 改完会补发 `input`
和 `change`（都 `bubbles`）。选项不存在时报错会把**现有选项列出来**。

#### 文件上传：`upload_file`

```python
s.upload_file("#avatar", "/data/uploads/me.png")
```

⚠️ **路径是「浏览器所在那台机器」上的路径，不是跑脚本这台。** 浏览器在容器里跑的
时候，文件得先进容器（挂卷或 `docker cp`）。

⚠️ **浏览器不校验路径存在。** 实测传一个不存在的路径，CDP 不报错、`FileList` 里
照样多出一项，只是 `size` 为 0 —— 表单于是上传了一个空文件，而脚本这边一切正常。
`upload_file()` 会读回来查一遍，0 字节直接报错；真要传空文件用 `allow_empty=True`。

走 `DOM.setFileInputFiles`，不是伪造 `change`：`FileList` 在 JS 里造不出来，伪造的
事件里 `files` 是空的。

#### 刷新与前进后退

```python
s.reload()                       # 相当于 F5
s.reload(ignore_cache=True)      # 相当于 Ctrl+Shift+R
s.back(); s.forward()
s.history()                      # (当前下标, 条目列表)
```

**`reload()` 和 `open(当前地址)` 不是一回事。** `Page.navigate` 到同一个 URL 会命中
缓存，语义是"再去一次"。想复现"手动按 F5"（比如观察每次刷新出口 IP 变不变）就得用
`reload`，别再靠"URL 挂个唯一查询参数"去近似 —— 那改的是 URL，不是缓存语义。

`back()` / `forward()` 会**先查历史**再跳：越界直接报错并告诉你现在在第几条，而不是
静默不动。只差 fragment 的两条历史是同文档跳转，不产生任何 lifecycle 事件，库会认出来
并直接返回，不会傻等到超时。

> ⚠️ **地址会重定向时，别拿 `DomReady` / `Load` 当完成信号。** 一次重定向是两次文档
> 提交，中间那个文档也可能发出自己的 `DOMContentLoaded`，于是导航在链条走完之前就
> 返回了。真机上量过：`http://example.com/` 刷新有 3/8 的复现率，直接访问
> `https://example.com/` 是 0/8。这不是 sleight 特有的，任何 CDP 客户端都一样。
> 要可靠就等页面自己的东西：
>
> ```python
> s.reload(wait=Selector("#article-body"), timeout=60)
> ```

#### 运行期改视口

```python
s.set_viewport(1280, 2400)       # 拉高，一次性触发懒加载
...
s.clear_viewport()
```

⚠️ **这是渲染层的覆盖，改不了 `screen.width` / `screen.height`** —— 那两个是 profile
的指纹字段，由实例启动参数决定。所以"窗口比屏幕还大"这种组合是做得出来的，而它本身
就是一个特征。临时用可以，别当成"改分辨率"。

**撤掉覆盖 ≠ 尺寸变回去。** `clear_viewport()` 只保证"不再有覆盖"，之后窗口多大由
浏览器说了算。Chromium 146 + Xvnc 上实测（每次新 tab，重复 4 轮，`set(900,2400)`）：

| 轮次 | clear 之后 | |
|---|---|---|
| #0 | `(1928, 957)` | 弹回来了，但不等于覆盖前的 `(1920, 947)` |
| #1 | **`(900, 2400)`** | 根本没变 |
| #2 | `(1928, 957)` | |
| #3 | **`(900, 2400)`** | |

重复调 `clear` 没用（连发三次结果一样）。**别依赖撤销之后的尺寸** —— 要什么尺寸就
`set_viewport` 到什么尺寸。

### 5.15 批量清理与换身份

#### 批量删 profile：`prune_profiles`

```python
doomed = mgr.prune_profiles(name_prefix="reuters-test-")     # 默认只预演
for p in doomed:
    print(p["name"])

mgr.prune_profiles(name_prefix="reuters-test-", dry_run=False)
```

`dry_run=True` 是默认值而不是可选项：删 profile 会连带删掉 `user_data_dir`，登录态
一起没，**不可逆**。

**不给任何筛选条件会直接 `ValueError`** —— "删掉全部"必须是明写出来的意图，不能是
少传一个参数的后果。真要清空就给 `name_prefix=""`。

三个条件是**与**关系；`older_than` 读不出建立时间的 profile 不会被选中（看不懂就
不删）。中间某个删不掉只记 warning 继续，返回**实际删掉的**那些 —— 删了一半就抛异常
是批量清理最难收拾的状态。

#### 改完立刻生效：`restart=True`

```python
mgr.update_profile(pid, proxy="socks5://new:1080", restart=True)
```

`proxy` / `fingerprint_seed` 这类字段**不重启就不生效**，而 Manager 只提示不执行 ——
改完以为生效了、其实还在用旧代理，是这里最容易出的静默错误。实例本来就没在跑的话
只改配置，不会顺手把它拉起来（那要占一份内存，是另一个决定）。

#### 每个实例一个全新身份

```python
from sleight.providers import ProfileSpec

specs = [ProfileSpec.randomized(f"scrape-{i:02d}", "windows_hk") for i in range(10)]
```

`fingerprint_seed` 三种取值：

| 值 | 含义 |
|---|---|
| `None`（默认） | 不下发，Manager 说了算 |
| 整数 | **可复现，也意味着可被长期追踪** |
| `"random"` | 下发前现摇一个（用 `secrets`，不是 `random`） |

这个权衡没有普适答案：调试要可复现，采集要不可追踪。要留意的是**固定 seed 意味着
重启换了 IP、清了 cookie 之后，canvas/WebGL 指纹仍然是同一个** —— 站点照样认得出这是
同一台"机器"。更别把同一个整数复用到一批 profile 上，那等于给它们发了同一张身份证。

> `"random"` 的语义是「**建的时候**摇一个」。`ensure_profile()` 对已存在的 profile
> **不会**重摇 —— 否则每跑一遍脚本指纹就变一次，幂等就没了。

### 5.16 常用操作片段

下面这些是从实际脚本里提炼的，直接抄。统一约定：

import os
from sleight.providers import CloakBrowserManager

BASE = os.environ.get("CLOAK_BASE", "http://127.0.0.1:19000")

#### 列出全部 profile，看某一个在不在

```python
def profile_list(mgr, wanted_id: str | None = None) -> None:
    profiles = mgr.list_instances()
    print(f"{len(profiles)} profile(s) on {mgr.base_url}")
    for p in profiles:
        print(f"  {p.id}  {p.name or '-':24} {'running' if p.ready else 'stopped':8} {sorted(p.tags)}")

```

#### 按名字取唯一的 profile

三个脚本里重复三遍的那段查找，抽出来：

```python
from sleight.core.errors import NotFound

def profile_by_name(mgr, name: str):
    """按名字取**唯一**匹配。重名直接报错 —— 名字是你自己的路由键，重了就该修数据。"""
    matches = [p for p in mgr.list_instances() if p.name == name]
    if not matches:
        raise NotFound(f"no profile named {name!r}")
    if len(matches) > 1:
        raise NotFound(f"{name!r} is ambiguous: {[p.id for p in matches]}")
    return matches[0]
```

有了它，后面所有片段都是一行 `info = profile_by_name(mgr, NAME)`。

> 想避免重名，用 `ensure_profile()` 而不是 `create_profile()` —— 后者对同名会
> **再建一个**。

#### 幂等地准备一个 profile

```python
from sleight.providers import ProfileSpec

def prepare(mgr, name: str):
    spec = ProfileSpec.macos_us(
        name,
        proxy=os.environ["CLOAK_PROXY"],          # socks5://user:pass@host:port
        tags=("sleight", "scrape"),
        notes="由 prepare() 建，可随时重跑",
    )
    return mgr.ensure_profile(spec)               # 有则更新差异字段，无则创建
```

#### 用完就停

`release()` 不会停实例（持久化登录态在里面），停是显式的运维动作：

```python
def visit_then_stop(mgr, name: str, url: str) -> str:
    info = profile_by_name(mgr, name)
    try:
        with mgr.lease(instance_id=info.id, timeout=60) as inst:
            with inst.session(human=True) as s:
                s.open(url, timeout=60)
                return s.title()
    finally:
        mgr.stop(info.id)          # 放在 finally：中途抛异常也要停
```

`mgr.stop()` 对**已经停了**的实例是幂等成功，对**不存在**的 id 抛 `NotFound` ——
所以打错 id 不会被静默吞掉。

#### 抓完页面但把标签页留着（人工接着看）

`inst.session()` 建的 tab 退出时会被关掉。想留着人工用 VNC 接着看，就自己建 target
再 `attach()` —— `attach` 出来的 Session 退出时只 detach，不关页面：

```python
def visit_keep_open(mgr, name: str, url: str) -> tuple[str, str]:
    """返回 (渲染后 HTML, 留下的 targetId)。租约释放，页面和 profile 都留着。"""
    info = profile_by_name(mgr, name)
    with mgr.lease(instance_id=info.id, timeout=60) as inst:
        target_id = inst.transport.call("Target.createTarget", {"url": "about:blank"})["targetId"]
        with inst.attach(target_id) as s:
            s.open(url, wait=Load(), timeout=90)
            s.wait(NetworkIdle(quiet=1.0), timeout=60)     # 比 sleep 固定秒数准
            return s.content(), target_id
```

下次想接着操作这个页面：

```python
with mgr.lease(instance_id=info.id) as inst:
    print([t["url"] for t in inst.targets()])        # 挑一个
    with inst.attach(target_id) as s:
        s.click("#next-page")
```

> **等渲染完别用 `time.sleep(5)`。** 有条件就写条件：`wait(Text("某个必然出现的词"))`
> 最直观，`wait(Selector(".result"))` 最准，`wait(NetworkIdle())` 适合 XHR 密集的页面。
> 固定 sleep 在慢网络下不够、在快网络下白等。

#### 完整脚本骨架

```python
"""用 sleight 操作 CloakBrowser profile。凭据全部走环境变量。"""

from __future__ import annotations

import os

from sleight import Load, NetworkIdle, NetworkResource
from sleight.core.errors import NotFound
from sleight.providers import CloakBrowserManager, ProfileSpec

BASE = os.environ.get("CLOAK_BASE", "http://127.0.0.1:19000")
NAME = os.environ.get("CLOAK_PROFILE_NAME", "scrape-01")
TARGET = os.environ["TARGET_URL"]
LISTEN_SECONDS = float(os.environ.get("LISTEN_SECONDS", "10"))


def profile_by_name(mgr, name: str):
    matches = [p for p in mgr.list_instances() if p.name == name]
    if len(matches) != 1:
        raise NotFound(f"{name!r} matched {len(matches)} profile(s)")
    return matches[0]


def main() -> None:
    mgr = CloakBrowserManager(BASE)               # token 从 SLEIGHT_CLOAK_TOKEN 读

    # 幂等准备
    spec = ProfileSpec.macos_us(NAME, proxy=os.environ["CLOAK_PROXY"], tags=("scrape",))
    info = mgr.ensure_profile(spec)

    def show(r: NetworkResource) -> None:
        if label := {"Script": "js", "Stylesheet": "css"}.get(r.resource_type):
            print(f"[{label}] {r.url}")

    with mgr.lease(instance_id=info.id, timeout=60) as inst:
        with inst.session(human=True) as s:
            with s.capture_resources(types={"Script", "Stylesheet"}, on_discovered=show) as cap:
                s.open(TARGET, wait=Load(), timeout=90)
                s.wait(NetworkIdle(quiet=1.0), timeout=60)
                s.pump_events(LISTEN_SECONDS)

            print(f"title={s.title()!r} html={len(s.content())} chars")
            print(f"js={len(cap.urls('Script'))} css={len(cap.urls('Stylesheet'))}")


if __name__ == "__main__":
    main()
```

## 7. 错误处理

```
SleightError
├── ConnectionError      端点不可达、隧道断
├── AuthError            401 / 403
├── ProtocolError        CDP 返回了 error，或消息不符合协议
├── InstanceError
│   ├── NotFound         instance_id 不存在（只由 status() 判定）
│   ├── NotReady         实例未启动
│   ├── Busy             租约被占
│   └── Crashed          实例 running 但 CDP 不通
├── SessionLost          连接已恢复，但会话状态丢失
├── LeaseLost            续租失败，本 handle 已失效
├── LeaseStillHeld       释放租约时仍有活动 Session（严格模式）
├── TimeoutError         等待条件超时，带 last_value
└── ElementError         选择器没命中 / 不可交互 / 被遮挡
```

```python
from sleight import errors               # errors.NotFound / errors.Busy / …
from sleight.core.errors import NotFound, Busy, ElementError
```

> 注意是 `sleight.core.errors`，不是 `sleight.errors` —— 后者只是顶层包里的一个属性
> 别名，`from sleight.errors import X` 会 `ModuleNotFoundError`。

> `sleight.errors.ConnectionError` 和 `TimeoutError` **有意遮蔽**内建同名异常，
> 给包内一个统一入口。`except Exception` 照样能接住，因为它们都继承 `Exception`。

### 只重试幂等操作

| 操作类别 | 例 | 断连后 |
|---|---|---|
| **幂等** | `list_instances` / `status` / `attach` / 只读 `eval` | 可以自动重试 |
| **非幂等** | `click` / `type` / `press` / `open` / 表单提交 | **绝不自动重放** |

sleight 不知道哪个 `click` 是安全的——重放可能意味着付了两次款、发了两条消息、
提交了两次表单。`recover()` 只负责把实例和连接恢复到可用状态，业务上从哪个检查点
继续由你决定。

### 隧道抖动 ≠ 浏览器崩溃

```
CDP 无响应
  ├─ Manager 也连不上          → ConnectionError（什么都别重启，是网络问题）
  ├─ status() = NOT_FOUND      → NotFound
  ├─ status() = STOPPED        → NotReady   → ensure_ready() 拉起
  └─ status() = RUNNING 但 CDP 不通 → Crashed → recover()
```

`recover()` 会 stop → launch → 等就绪。这是运维级操作，会丢掉浏览器里的所有 tab
（但不丢 `user_data_dir` 里的登录态）。

```python
from sleight.core.types import InstanceStatus

try:
    with mgr.lease(instance_id=pid) as inst:
        with inst.session() as s:
            s.open(url)
except errors.ConnectionError:
    if mgr.status(pid) is InstanceStatus.RUNNING:
        mgr.recover(pid)          # 浏览器僵了
    # 否则是网络问题，等一会儿重试
```

## 8. 排错手册

| 症状 | 原因 | 怎么办 |
|---|---|---|
| WS 握手 403 | Manager 的 WS 升级也要 `Authorization` 头，凭据塞不进 URL | 确认 `token` 传对了；`CloakBrowserManager` 会自动带 |
| `AuthError: 401 from …` | token 不对或过期 | 检查 `SLEIGHT_CLOAK_TOKEN` |
| `NotFound: no instance 'xxx' in this pool` | id 打错，或那个 profile 已被删 | `mgr.list_instances()` 看一眼 |
| `lease()` 一直不返回 | 实例全被占，默认阻塞等 | 加 `timeout=` 或 `block=False` |
| `NotReady: nothing answering at …/json/version` | `Plain` 起不了浏览器 | 自己把 Chrome 拉起来 |
| `InstanceError: instance … not ready after 60s` | Manager 起 profile 超时 | 看 Manager 日志；`/dev/shm` 满了是常见原因 |
| 点击"没反应" | 目标被遮挡 | 看 `ElementError` 消息里点名的那个元素，先关掉 cookie 横幅 |
| `ElementError: … does not have focus` | 点了个不可聚焦的元素就 `clear=True` | 换一个真正的 `<input>` 选择器 |
| `ElementError: … will not scroll into view` | 元素在嵌套滚动容器里，或横向出界 | 试 `human=False` 走 `DOM.scrollIntoViewIfNeeded` |
| `wait()` 一路超时 | 条件写错，或页面确实没加载 | 看异常的 `last_value`；先用 `s.text()[:200]` 确认页面内容 |
| `NetworkIdle` 永远不满足 | 页面有长轮询 | 换 `Selector()` / `Text()` 条件 |
| `RuntimeError: Transport is not thread-safe` | 跨线程共用 Session | 每个线程 `lease()` 自己的实例 |
| `LeaseLost` | 续租失败，连接已被掐断 | **不要重试这次操作**，重新 `lease()` |
| 坐标点偏了 133 px | 用了 `screen_height` 而不是 viewport 高度 | 用 `s.viewport()` 或 `spec.viewport_height` |

### A.5 开发机访问（SSH 隧道）

B 的宿主机端口只监听 `127.0.0.1:9000`。A 先连 OpenVPN，再用一条 SSH 隧道同时承载

Windows 批处理：

```bat
@echo off
title CloakBrowser Manager SSH Tunnel

set "HOST=manager.example.com"
set "USER=deploy"
set "SSH_PORT=22"
set "KEY=%USERPROFILE%\.ssh\id_ed25519"

set "LOCAL_PORT=19000"
set "REMOTE_PORT=9000"

echo Starting SSH tunnel...
echo Local URL: http://127.0.0.1:%LOCAL_PORT%

start "" cmd /c "timeout /t 3 /nobreak >nul && start http://127.0.0.1:%LOCAL_PORT%"

ssh ^
  -i "%KEY%" ^
  -N ^
  -T ^
  -p %SSH_PORT% ^
  -o ExitOnForwardFailure=yes ^
  -o ServerAliveInterval=30 ^
  -o ServerAliveCountMax=3 ^
  -L 127.0.0.1:%LOCAL_PORT%:127.0.0.1:%REMOTE_PORT% ^
  %USER%@%HOST%

echo SSH tunnel closed.
pause
```

```bash
ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:19000:127.0.0.1:9000 deploy@manager.example.com
```

```

  ↓ SSH 隧道

Manager 8080
```

所有 Profile 共用这一条隧道。关掉 SSH 进程，Web UI、CDP 和 noVNC 全部断开。

sleight 侧：

```bash
export SLEIGHT_CLOAK_TOKEN=替换为开发Token
```

```python
mgr = CloakBrowserManager("http://127.0.0.1:19000")   # token 从环境变量读
```

### A.6 生产任务节点访问

C 与 B 同一私网时不用 SSH 隧道，B 直接把端口绑到私网接口：

```yaml
ports:
  - "10.0.0.12:9000:8080"
```

```bash
export SLEIGHT_CLOAK_TOKEN=替换为生产Token
```

```python
mgr = CloakBrowserManager("http://10.0.0.12:9000")
```

B 的防火墙只允许 C 的固定私网地址访问 9000。A 与 C 用同一套业务代码，只通过环境变量
切换 Manager URL。

> ⚠️ **`AUTH_TOKEN` 在 HTTP 上是明文传输的。** 只要流量可能经过不可信网络，就必须用
> SSH 隧道、VPN 或 HTTPS 反向代理。Token 认证不能替代传输加密。

### A.7 资源与监控

`shm_size: 5gb` 是**整个容器共享**的 `/dev/shm`，不是每个 Profile 5 GB：

```
Profile 1 ─┐
Profile 2 ─┼─ 共享 5GB /dev/shm
Profile 3 ─┘
```

官方 README 给的粗略下限是每个运行 Profile 约 512 MB RAM，但真实页面、标签数量、
视频、Canvas 和缓存会显著改变占用。三个 Profile 可用 8 GB RAM 起步，**建议 16 GB
作为更稳妥的生产基线**，最终容量按峰值压测定。

```bash
curl --fail http://127.0.0.1:9000/api/status
docker compose ps
docker inspect --format '{{if .State.Health}}{{.State.Health.Status}}{{else}}no-healthcheck{{end}}' cloakbrowser-manager
docker exec cloakbrowser-manager df -h /dev/shm
docker stats --no-stream cloakbrowser-manager
```

重点监控：`/dev/shm` 使用率、容器 RSS、CPU 峰值、宿主机剩余内存、Manager 健康状态、
运行 Profile 数、启动失败次数、CDP 断开次数、任务 P95/P99、超时率、`/data` 磁盘容量。

### A.8 数据持久化与备份

必须把完整 `/data` 映射到宿主机：

```yaml
volumes:
  - ./data:/data
```

这个目录包含 Profile 数据库、Profile ID、指纹种子、Cookie、LocalStorage、IndexedDB、
浏览器用户目录、代理配置和登录状态。容器重建时没挂它就是**丢全部 Profile 数据**。

多个 Manager 必须用不同的数据目录：

```
manager-01 → ./data/manager-01
manager-02 → ./data/manager-02
```

停机归档整个目录：

```bash
cd /srv/cloakbrowser-manager
docker compose stop manager

tar -czf "backups/cloakbrowser-$(date +%Y%m%d-%H%M%S).tar.gz" data

docker compose start manager
docker compose ps
```

> ⚠️ **上面那条 `tar` 必须以 root 跑。** `data/profiles/<id>/` 里的浏览器用户目录是
> Manager 以 root 身份写的，普通用户执行会一路 `Permission denied`，**而且 tar 会留下
> 一个残档** —— 实测只有 12 条 / 1.9 KB（完整的是 238 条 / 134 KB），看着和真备份一样。
> 手工做就前面加 `sudo`；`sleight backup` 是借一个一次性 root 容器做的，不需要 sudo，
> 失败也不留残档。

**不要只在线复制 SQLite 文件。** 数据库和浏览器用户目录必须处于一致的时间点；
当前规模下，停机归档完整 `data` 是最简单可靠的方案。

### A.9 升级与回滚

**版本基线**（截至 2026-07-27，`latest` 与之同摘要）：

```
cloakhq/cloakbrowser-manager:v0.0.10
sha256:44836e982192e8fedb28617f2d39192bdef91f8dd62cf36c522c96d7d8e15914
```

生产优先固定版本标签；需要完全可复现时进一步固定摘要：

```bash
MANAGER_IMAGE=cloakhq/cloakbrowser-manager:v0.0.10@sha256:44836e982192e8fedb28617f2d39192bdef91f8dd62cf36c522c96d7d8e15914
```

**不要**进入运行中的容器执行 `pip install` 或 `python -m cloakbrowser update`。那会
产生不可复现的容器漂移，下次重建就丢。

升级前：暂停任务分发、等租约结束、记录旧镜像摘要、做一次完整 `/data` 停机备份。

```bash
# 先把 MANAGER_IMAGE 改成新版本标签或摘要
docker compose config
docker compose pull manager
docker compose up -d --no-deps --force-recreate manager
docker compose ps
docker compose logs --tail=200 manager
curl --fail http://127.0.0.1:9000/api/status
```

验收至少覆盖：容器 healthy、Profile 数量/ID/代理未变、抽样 Profile 能启动并通过 CDP
操作、Cookie 和登录状态仍可用、任务耗时和失败率没有异常上升。**先恢复少量任务观察
错误率，再恢复全部流量。**

镜像回滚：把 `MANAGER_IMAGE` 改回旧标签或摘要，重新 `pull` + `up -d --force-recreate`。

数据回滚（只在镜像回滚不足以恢复时用）：

```bash
docker compose stop manager
mv data "data.failed-$(date +%Y%m%d-%H%M%S)"       # 保留失败现场
tar -xzf backups/升级前备份文件.tar.gz
docker compose start manager
```

**不要执行 `docker compose down -v`**，也不要在没有有效备份时删 `data`。

### A.10 上线检查清单

- [ ] Manager 使用明确版本标签或镜像摘要，不依赖 `latest`
- [ ] `AUTH_TOKEN` 足够随机，`.env` 权限 600，且未进入 Git
- [ ] 开发访问走 VPN + SSH；生产访问只走私网和防火墙白名单
- [ ] 9000 未直接暴露到公网；非可信网络已用 HTTPS 或隧道
- [ ] 完整 `/data` 已持久化，不存在多个 Manager 共享同一目录
- [ ] 备份、镜像回滚和数据回滚至少演练一次
- [ ] 使用原子租约，且租约可以超时回收（sleight 的 `Pool` 已内建）
- [ ] 单 Profile 同一时间只有一个任务
- [ ] Manager、Profile、CDP、任务与资源指标已纳入监控
- [ ] 已用真实目标页面完成并发、内存、shm、超时与恢复压测

### A.11 扩容路线

| 活跃 Profile | 推荐形态 | 重点 |
|---|---|---|
| 3 | 1 台 B、1 个 Manager、3 个 Profile | 5 GB shm |
| 约 5 | 1 台 B、1 个 Manager、5 个 Profile | 建议 16 GB RAM，按压测调 shm |
| 约 10 | 2 个 Manager 或 2 台 B，各约 5 个 Profile | 独立端口、独立 `/data`，缩小故障域 |
| 几十个 | Pool 管理多台 B | 业务代码不直接选 Manager URL |
| 约 100 | 中央队列 + 每台 B 本地 Worker Agent | CDP 操作留在 B，只回传结构化结果 |

到较大规模时，每台 B 建议跑一个本地 Worker Agent，与本机 Manager 和 4~8 个 Profile
通信。这能减少跨机器 CDP WebSocket、避免任务节点成为网络瓶颈，并把网络波动限制在
单个浏览器节点内。

当前规模**不需要 Kubernetes**，也不需要为每个 Profile 映射独立端口。优先把版本固定、
网络边界、任务租约、备份回滚和真实压测做扎实。

### CDP 地址与鉴权

**所有实例共用 Manager 的同一个端口**，靠 URL path 区分——不是每实例一个端口。
多实例只需要一条隧道。

```
ws://HOST/api/profiles/{id}/cdp                            浏览器级 WS
http://HOST/api/profiles/{id}/cdp/json/version             版本
```

| 请求 | 无 token | 有 Bearer |
|---|---|---|
| `GET /api/profiles` | 401 | 200 |
| `GET …/cdp/json/list` | 401 | 200 |
| **WS Upgrade `…/cdp`** | **403** | **101** |

> ⚠️ **不要用 `/json/version` 返回的 `webSocketDebuggerUrl`。** Manager 把它重写成
> `ws://127.0.0.1:19000/...`——host 是**写死的**，换隧道端口或内网直连就错。
> sleight 用 `base_url` 自己拼，不碰这个字段。

### 幂等语义（实测）

| 操作 | 前置状态 | 状态码 | body |
|---|---|---|---|
| `POST launch` | stopped | 200 | `{profile_id, status:"running", …}` |
| `POST launch` | **running** | **409** | `{"detail":"Profile is already running"}` |
| `POST launch` | id 不存在 | 404 | `{"detail":"Profile not found"}` |
| `POST stop` | running | 200 | `{"ok":true}` |
| `POST stop` | **stopped** | **404** | `{"detail":"Profile is not running"}` |
| `POST stop` | **id 不存在** | **404** | `{"detail":"Profile is not running"}` ← 同上！ |
| `GET status` | id 不存在 | 404 | `{"detail":"Profile not found"}` |
| `GET …/cdp/json/version` | stopped | 404 | `{"detail":"Profile not running"}` |

三个结论，也是 sleight 内部实现的依据：

1. **`stop` 的 404 分不清「已停止」和「id 不存在」**，detail 完全相同。判定存在性
   只能用 `GET status`。sleight 的 `stop()` 因此会在 404 之后回头查一次 `status()`，
   而不是把打错的 id 静默当成幂等成功。
2. **停止的实例访问 CDP 返回 404，不是 401/502**，映射到 `NotReady` 而非 `Crashed`。
3. `POST /api/profiles` 传 `auto_launch: false` 可建一个不自动启动的 profile，
   适合做探测，不打扰正在跑的实例。

### 其它可观察量

| 字段 | 说明 |
|---|---|
| `cdp_url` | **相对路径** `/api/profiles/{id}/cdp` |
| `vnc_ws_port` / `display` | 分配规律：`6100+N` / `:100+N` |
| `screen_width` / `screen_height` | 坐标基准（1920×1080 → viewport 1920×947） |
| `tags` | `[{tag, color}]`，sleight 只取 `tag` 列 |

`/openapi.json` 可以取，但 **`securitySchemes` 是空的**——spec 没声明鉴权而实际强制，
不能直接拿它生成客户端。

## 9. 已知限制与未来计划

### 已知限制

都是实测出来的，不是推测。每一条都有人花过一天才弄明白：

| | |
|---|---|
| **上下文里用不了扩展** | `Target.createBrowserContext` 建的是无痕上下文，Chrome 默认不在无痕里启用扩展。同一个 profile、同一个 URL：`chrome-extension://<id>/…` 在默认 context 打得开，在新 context 里是 `ERR_BLOCKED_BY_CLIENT`。所以**换出口和用插件互斥** —— 依赖插件就靠多开 profile、各配各的上游代理来换出口。见 [5.12](#512-换出口-ip浏览器上下文) |
| **重定向时 `reload()` 可能提前返回** | 一次重定向是两次文档提交，中间那个也可能发自己的 `DOMContentLoaded`。实测 `http://` → `https://` 复现 3/8，不重定向 0/8。这不是 sleight 特有的。在意就等页面自己的东西（`Selector` / `Text`） |
| **`block()` 只在 sleight 跟浏览器说话时生效** | 被暂停的请求要靠事件泵拿裁决，而事件泵跑在 `open` / `wait` / `pump_events` 和每次 `call` 里。纯 `time.sleep()` 期间请求会挂着 |
| **`Transport` 归属创建它的线程** | 是**强制**的不是"建议"：跨线程用当场抛 `RuntimeError`。每线程租自己的实例。`Pool` 和锁表则是刻意共享的。见 [5.5](#55-多线程并发跑一批任务) |
| **`set_viewport()` 改不了 `screen.*`** | 那是渲染层覆盖。屏幕尺寸是 profile 的指纹字段，启动时定死 |

### 未来计划

按"挡不挡事"排，不按工作量排。

**① iframe / frame 支持** —— `s.frames()`、`with s.frame(sel) as fs:`。唯一的真缺口。
验证码基本都在 iframe 里（DataDome 的就是），所以 `drag` 和元素截图虽然都做好了，
**够不着 iframe 里的滑块**。要做的是 frame 树、跨 frame 坐标换算、OOPIF 各自一条 session。

**② 上下文 vs 轻量实例的资源账** —— 内存、CPU、就绪耗时三档对比：*带代理带插件的实例*
/ *裸实例* / *一个实例里 N 个上下文*。没有这张表就不该照着上下文重构并发架构，
所以在数字出来之前，上下文一直是**可选维度**，`Pool` 的租约粒度不动。

**③ `launch_args_effective`** —— `get_profile()` 返回的是**配置的**启动参数；真正生效的
命令行在 Manager 侧。现在排查代理问题只能去读 `chrome://version`。
