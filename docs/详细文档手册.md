## 1. 这个库解决什么问题

浏览器层的反检测已经有成熟方案（CloakBrowser 的源码级 Chromium patch、Camoufox 的
Juggler patch），它们解决**指纹**——浏览器长什么样。没有人解决**行为**——它怎么动。

- Playwright / Puppeteer 的默认鼠标是**瞬移**；`mouse.move(steps=N)` 是**匀速直线**，
  零抖动、加速度恒为 0。匀速直线本身就是特征。
- **浏览器不会替你补轨迹。** 即便浏览器侧开了 humanize，外部 CDP 客户端在 press 与
  release 之间产生的 `mousemove` 事件是 **0 条**（实测，不是推测）。
- 轨迹库生态在 JS 侧（`ghost-cursor`），Python 侧移植维护薄弱。
- Crawlee for Python 的 `BrowserPool`
  [不支持远程浏览器](https://github.com/apify/crawlee-python/issues/1743)。

sleight 补的就是这个位置：**Python + 远程 CDP + 拟人行为 + 实例租约**。

### 做什么 / 不做什么

| 做 | 不做 | 不做的话交给谁 |
|---|---|---|
| 连接任意 CDP 端点 | 数据抽取 / 清洗 | parsel / pyquery / selectolax |
| 导航、类型化等待、读渲染后 DOM | 定时调度、队列、去重、入库 | APScheduler / Celery |
| 拟人鼠标 / 键盘 / 滚轮 | 完整的定位 DSL | Playwright |
| 实例发现、跨 Manager 聚合 | 指纹伪装 | 浏览器自己的事 |
| 协作式排他租约 | iframe / OOPIF / Shadow DOM 穿透 | Playwright |
| 故障分类与幂等恢复 | 严格 fencing（强制驱逐旧持有者） | 需要在浏览器节点部署转发 Agent |
| | WebDriver BiDi、Firefox | Playwright-Firefox |

**与 Playwright 的关系是补位，不是替代。** sleight 的 `human` 模块是
[sans-io](https://sans-io.readthedocs.io/) 的——它只产出 `(method, params, sleep_after)`
三元组，从不碰 socket，所以它可以直接驱动 Playwright 的 `CDPSession`。

## 2. 安装

```bash
pip install sleight
```

用 uv：

```bash
uv add sleight
```

可选依赖：

| extra | 装什么 | 什么时候要 |
|---|---|---|
| `redis` | `redis>=5` | 多进程 / 多机共享同一批浏览器实例时的跨进程租约 |
| `dev` | `pytest` `ruff` | 开发与测试 |

```bash
pip install "sleight[redis]"
```

从源码装：

```bash
git clone git@github.com:yuanqimanong/sleight.git
cd sleight
uv sync --extra dev
uv run pytest
```

**依赖只有一个是有意为之。** 实测三方 HTTP 库的代价：`urllib.request` 装 0 个包，
`httpx` 装 6 个，`niquests` 装 7 个（含两个 Rust 编译扩展）。Provider 每分钟只发几个
HTTP 请求，用不上连接池和 HTTP/2。

## 3. 快速开始

### 最短的能跑的代码

先起一个开了调试端口的 Chrome：

```bash
chrome --remote-debugging-port=9222
```

然后：

```python
from sleight import connect

with connect("http://127.0.0.1:9222") as s:   # 自建 tab，退出自动关闭
    s.open("https://example.com")
    print(s.title(), len(s.content()))
```

### 加上拟人

```python
from sleight import connect, Text

with connect("http://127.0.0.1:9222", human=True) as s:
    s.open("https://example.com", wait=Text("Example Domain"))
    s.hover("h1")                      # 贝塞尔轨迹 + 手抖，几十个 mousemove
    s.click("a")                       # 落点是 bbox 内的截断高斯，不是正中心
```

### 连 CloakBrowser Manager

```python
from sleight.providers import CloakBrowserManager

mgr = CloakBrowserManager("http://127.0.0.1:19000", token="…")

with mgr.lease() as inst:              # 排他租约，退出自动释放
    with inst.session(human=True) as s:
        s.open("https://example.com")
        s.type("#email", "user@example.com")
        s.click("#submit")
```

## 4. 五层结构

```
Provider          发现 / 状态 / 启停 / Endpoint。不做选择，不持锁。
   ↓
Pool              唯一的实例选择者。持有长期 LeaseStore。产出 InstanceHandle。
   ↓
InstanceHandle    持有租约，跟踪自己创建的 Session，负责关闭顺序。
   ↓
Session           默认创建自有 tab。管 target / sessionId / transport。
   ↓
Transport         call / send_no_wait / flush。
   ↑
Human             纯算法。不接触 Transport / Provider / Lease。
```

| 层 | 职责 | 关键约束 |
|---|---|---|
| **Provider** | 告诉你有哪些实例、它们的状态、CDP 地址在哪，以及怎么启停 | **没有 `lease()`**。`mgr.lease()` 是转发到懒建单例 Pool 的便利方法 |
| **Pool** | 唯一的选择者。first-free，按 provider 打散起始下标 | **全生命周期持有同一个 LeaseStore**——锁表归属单次调用的话排他直接失效 |
| **InstanceHandle** | 一次租用。懒建 WS 连接，跟踪 Session | 关闭顺序硬性：Session → 续租线程 → WS → `provider.release()` → `lease.release()` |
| **Session** | 一个 tab 上的操作。**不是线程安全的，也不需要是** | 一个实例同时只给一个 Session |
| **Human** | 纯算法，不 import transport / provider / lease | 产物是事件三元组，谁发、发到哪它不知道 |

### 三条容易踩的所有权规则

1. **一个实例同时只给一个 Session。** 两个客户端同时控一个浏览器会互相切页面。
   并发的正确写法是每个线程 `lease()` 自己的实例（见 [5.5](#55-多线程并发跑一批任务)）。
2. **`release()` 默认不停实例。** 持久化登录态在浏览器里，停了下次要重新登录。
   停实例是运维动作，用 `mgr.stop(id)` 显式做。
3. **`Session` 默认新建自己的 tab，退出时关掉它。** 接管既有 tab 必须显式
   `inst.attach(target_id)`，那种 Session 退出时只 detach，不关页面。

## 5. 实战场景

### 5.1 本地 Chrome 跑通第一个脚本

调试期最方便的后端就是本机 Chrome。

```bash
# macOS
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
  --remote-debugging-port=9222 --user-data-dir=/tmp/sleight-profile

# Windows
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --remote-debugging-port=9222 --user-data-dir=%TEMP%\sleight-profile

# Linux
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/sleight-profile
```

> `--user-data-dir` 一定要给。不给的话 Chrome 会复用你日常那个 profile，调试脚本
> 就在你自己的登录态上乱点。

```python
from sleight import connect, Selector

with connect("http://127.0.0.1:9222", human=True) as s:
    s.open("https://example.com", wait=Selector("h1"))

    print("标题:", s.title())
    print("地址:", s.url())
    print("正文前 80 字:", s.text()[:80])

    link = s.query("a")
    if link:
        print("链接几何:", link.box())
        s.click(link)                            # 跟随 Session 默认（拟人）
        s.wait(Selector("body"), timeout=10)

    s.screenshot("shot.png")
```

`connect()` 也接受直接的 `ws://` 浏览器级端点：

```python
with connect("ws://127.0.0.1:9222/devtools/browser/abc-123") as s:
    ...
```

`Plain` provider 还支持带鉴权头的裸端点（browserless 那类）：

```python
from sleight.providers import Plain

p = Plain("https://chrome.browserless.io", headers={"Authorization": "Bearer …"})
with p.lease() as inst:
    with inst.session() as s:
        s.open("https://example.com")
```

### 5.2 只有 Manager 地址和 token，怎么开始

**够了。** 实例发现、WS 地址拼装、Bearer 握手头、未运行 profile 的拉起，
`CloakBrowserManager` 全包了。

```python
from sleight.providers import CloakBrowserManager

mgr = CloakBrowserManager(
    "http://127.0.0.1:19000",
    token="…",                 # 不给就读环境变量 SLEIGHT_CLOAK_TOKEN
)
```

| 构造参数 | 说明 |
|---|---|
| `base_url` | Manager 根地址。尾部斜杠会被去掉 |
| `token` | Bearer token。**必需**——WS 握手不带它直接 403 |
| `name` | 池内唯一的 provider 名，默认 `"cloakbrowser"`。也是 uid 前缀 |
| `timeout` | HTTP 超时，秒，默认 15 |
| `ca_bundle` | 自签证书的 CA 文件路径。只有连 https 私有 Manager 才用得上 |
| `verify` | `False` 关闭证书校验 |

先看看有什么：

```python
print(mgr.system_status())         # {'running_count': 1, 'binary_version': …}

for i in mgr.list_instances():
    print(i.uid, i.name, "running" if i.ready else "stopped", sorted(i.tags))
```

`list_instances()` 返回 `InstanceInfo`：

| 字段 | 含义 |
|---|---|
| `id` | profile 的 UUID |
| `provider` | 哪个 provider 报上来的 |
| `ready` | 是否 `status == "running"` |
| `name` | profile 名 |
| `tags` | `frozenset[str]`。Manager 存的是 `[{tag, color}]`，这里只取 `tag` |
| `uid` | `"{provider}:{id}"`，全局唯一，租约 key 的主体 |

随便租一个空闲的：

```python
with mgr.lease() as inst:
    print("租到了", inst.info.uid)
    with inst.session(human=True) as s:
        s.open("https://example.com")
```

> **token 不会进日志。** 所有异常消息和 `repr()` 都会走脱敏——`Endpoint.headers` 和
> `ws_url` 都是 `repr=False`，URL query 里的 token 只留头尾各 3 个字符。

### 5.3 指定某一个 profile 去发任务

参数是 `lease(instance_id=...)`，认的是 **profile 的 UUID**，不是名字。四种写法：

#### ① 已知 id

```python
with mgr.lease(instance_id="5edcc28a-8b31-4c9e-a1f0-77d2e6c04b19") as inst:
    with inst.session(human=True) as s:
        s.open("https://example.com")
```

裸 id 和 `"cloakbrowser:5edcc28a-…"` 这种 uid 形式都收。多 Manager 混池时用 uid 消歧。

#### ② 只知道名字 —— 用 `where=` 谓词

```python
with mgr.lease(where=lambda i: i.name == "Win-US-02") as inst:
    ...
```

`lease()` **没有 `name=` 参数**。Pool 只做 first-free 选择，一切筛选都压到 `where=`
这一个口子，避免它慢慢长成一个调度器。

#### ③ 按 tag 路由

```python
with mgr.lease(where=lambda i: "us" in i.tags) as inst:
    ...

# 组合条件
with mgr.lease(where=lambda i: "us" in i.tags and "banned" not in i.tags) as inst:
    ...
```

#### ④ 名字 → id，然后按 id 租

```python
raw = mgr.find_profile("Win-US-02")          # 原始 dict，找不到返回 None
if raw:
    with mgr.lease(instance_id=raw["id"]) as inst:
        ...
```

或者走幂等创建，顺手拿到 id（见 [5.4](#54-快速构建-profile以及怎么传参)）。

#### `lease()` 全部参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `where` | `None` | 作用在 `InstanceInfo` 上的谓词 |
| `instance_id` | `None` | 指定实例。裸 id 或 uid |
| `provider` | `None` | 只在这个 provider 里挑（多 Manager 场景） |
| `block` | `True` | `False` 表示拿不到立刻抛 `Busy` |
| `timeout` | `None` | 阻塞上限，秒。`None` 一直等，超时抛 `TimeoutError` |
| `ready_only` | `False` | `True` 跳过没在运行的实例 |

#### 三个必须知道的行为

**① profile 停着也能租。** 租到之后 Pool 会调 `ensure_ready()` 把它拉起来并等就绪
（默认最多 60 秒）。想只挑已经在跑的：

```python
with mgr.lease(instance_id=pid, ready_only=True) as inst:
    ...
```

**② 被别人占着时默认是阻塞等，不是立刻报错。**

```python
mgr.lease(instance_id=pid)                 # 一直等到它空出来
mgr.lease(instance_id=pid, timeout=30)     # 等 30 秒，然后抛 TimeoutError
mgr.lease(instance_id=pid, block=False)    # 立刻抛 Busy
```

**③ id 不存在抛 `NotFound`。** Pool 会先强制刷一次发现缓存再判定，所以刚建出来的
profile 不会被误判。

#### 租约的边界：协作式排他，不是强制隔离

租约只能约束**通过 sleight 访问的客户端**。它拦不住：

- 通过 VNC 直接操作浏览器的人
- 不走 sleight、自己连 CDP 的其它程序
- Manager 自带的 Web UI

它防的是**你自己的多个任务互相踩**，不是入侵防护。

机制上：TTL 默认 30 秒，后台线程按 TTL/3 续租；续租失败会立刻标记 `lease_lost`
**并关闭 WebSocket**——连接关了就发不出命令，比检查标志位可靠。此后所有操作抛
`LeaseLost` 而不是 `ConnectionError`，因为前者绝不能重试，后者可以。

### 5.4 快速构建 profile，以及怎么传参

#### 最短路径

```python
from sleight.providers import CloakBrowserManager, ProfileSpec

mgr = CloakBrowserManager("http://127.0.0.1:19000", token="…")

spec = ProfileSpec.windows_us(                       # ① 挑一个自洽的底子
    "Win-US-02",
    proxy="socks5://user:pass@hk.example:3000",      # ② 传参就是关键字参数
    fingerprint_seed=20260729,
    tags=("us", "prod"),
)
info = mgr.ensure_profile(spec)                      # ③ 按 name 幂等
with mgr.lease(instance_id=info.id) as inst:         # ④ 租它
    with inst.session(human=True) as s:
        s.open("https://example.com")
```

不落盘、不写 YAML——`to_payload()` 直接构造 JSON body POST 给 `/api/profiles`。

#### 四个预设工厂

它们的价值不是省字数，是**保证指纹自洽**：平台、时区、语言、GPU 串锁成同一台机器上
真会出现的组合。`platform="windows"` 配一串 Apple Metal renderer 是一眼就会被标记的
矛盾。

| 工厂 | 锁定的组合 |
|---|---|
| `ProfileSpec.windows_us(name, **kw)` | `America/New_York` + `en-US` + Windows + NVIDIA RTX 3070 (D3D11) |
| `ProfileSpec.windows_hk(name, **kw)` | `Asia/Hong_Kong` + `zh-HK` + Windows + Intel UHD 630 |
| `ProfileSpec.macos_us(name, **kw)` | `America/Los_Angeles` + `en-US` + macOS + Apple M2 Metal |
| `ProfileSpec.linux_us(name, **kw)` | `America/New_York` + `en-US` + Linux + Mesa llvmpipe |

`**kw` 覆盖任何一项，但**只覆盖你真要改的**——覆盖 `gpu_renderer` 而不改 `platform`
会被 `validate()` 当场拒掉。

#### 全部可传参数

只有 `name` 必填，其余 21 个可选。

| 组 | 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|---|
| **网络** | `proxy` | `str \| None` | `None` | `socks5://user:pass@host:port` |
| | `geoip` | `bool` | `False` | 由代理出口 IP 推导时区/语言 |
| **身份** | `timezone` | `str \| None` | `None` | `"America/New_York"` |
| | `locale` | `str \| None` | `None` | `"en-US"` |
| | `platform` | `"windows"/"macos"/"linux"` | `"windows"` | |
| | `user_agent` | `str \| None` | `None` | `None` = 浏览器自带，**推荐** |
| | `fingerprint_seed` | `int \| None` | `None` | 固定则指纹可复现 |
| **硬件** | `screen_width` | `int` | `1920` | |
| | `screen_height` | `int` | `1080` | viewport 高度 = 这个值 − 133 |
| | `gpu_vendor` | `str \| None` | `None` | 预设已填好，一般别动 |
| | `gpu_renderer` | `str \| None` | `None` | 同上 |
| | `hardware_concurrency` | `int \| None` | `None` | CPU 核数 |
| **行为** | `headless` | `bool` | `False` | |
| | `color_scheme` | `"light"/"dark"/None` | `None` | |
| | `clipboard_sync` | `bool` | `True` | |
| | `auto_launch` | `bool` | `False` | 默认不自动起，交给 `ensure_ready` |
| | `launch_args` | `tuple[str, ...]` | `()` | 额外的 Chromium 启动参数 |
| | `humanize` | `bool` | `False` | **浏览器侧**拟人，外部 CDP 拿不到 |
| | `human_preset` | `str` | `"default"` | 同上 |
| **元信息** | `tags` | `tuple[str, ...]` | `()` | Pool 的路由键 |
| | `notes` | `str \| None` | `None` | |

#### 六个坑

1. **`geoip=True` 不能同时手写 `timezone` / `locale`。** 两者会打架，`validate()`
   直接抛。预设工厂检测到 `geoip=True` 会自动跳过预填。`geoip` 没配 `proxy` 也会被拒
   ——没东西可推导。
2. **`humanize` / `human_preset` 对你没用。** 那是浏览器进程内部的拟人，外部 CDP
   客户端拿不到（实测 press 与 release 之间 0 条 move 事件）。拟人由 sleight 的
   `human=` 做。
3. **直接 `ProfileSpec(...)` 构造不校验。** 预设工厂当场校验，
   `create_profile` / `ensure_profile` 也校验。用 `replace()` 派生时校验推迟到下发。
4. **viewport ≠ screen_height。** Manager 实测差 133 px，用 `spec.viewport_height`
   拿准数（1080 → 947）。
5. **留 `None` 的字段不会下发。** `to_payload()` 丢掉 `None`，所以 `ensure_profile`
   也不会把服务端已有的值改回默认。想真正清空某个字段得显式
   `mgr.update_profile(id, user_agent=None)`。
6. **罕见分辨率只 `warning` 不报错。** 罕见本身就是熵，可能是你故意的。

#### `validate()` 拦什么

| 冲突 | 处理 |
|---|---|
| `platform="windows"` + GPU 串含 Apple / Metal | `ValueError` |
| `platform="macos"` + GPU 串含 Direct3D / D3D11 | `ValueError` |
| `platform="linux"` + GPU 串含 Direct3D / Metal | `ValueError` |
| `geoip=True` 同时手写 `timezone` / `locale` | `ValueError` |
| `geoip=True` 但没配 `proxy` | `ValueError` |
| `user_agent` 声明的系统与 `platform` 不符 | `ValueError` |
| 分辨率不在常见列表里 | `UserWarning` |

#### 批量派生

```python
BASE = ProfileSpec.windows_us("tmpl", tags=("us",), launch_args=("--lang=en-US",))

for i, proxy in enumerate(PROXIES, 1):
    mgr.ensure_profile(BASE.replace(
        name=f"Win-US-{i:02d}",
        proxy=proxy,
        fingerprint_seed=20260000 + i,     # 固定 seed → 指纹可复现，跑挂了能重放
    ))
```

之后按 tag 抢空闲的那一个，不用关心具体是哪台：

```python
with mgr.lease(where=lambda i: "us" in i.tags, timeout=60) as inst:
    ...
```

#### 改与删

```python
mgr.update_profile(info.id, proxy="socks5://new:3000", notes="换代理 2026-07-29")

mgr.stop(info.id)                            # 显式停止，运维动作
mgr.delete_profile(info.id)                  # running 的会被拒
mgr.delete_profile(info.id, force=True)      # 先 stop 再删
```

`delete_profile` 默认拒删 running 的实例：删 profile 会连带删掉 `user_data_dir`

### 5.5 多线程并发跑一批任务

**硬约束：`max_workers` ≤ 实例数。** 一个实例同时只给一个 Session，多了只会在
`lease()` 上排队，不会更快。

```python
from concurrent.futures import ThreadPoolExecutor
from sleight.providers import CloakBrowserManager

mgr = CloakBrowserManager("http://127.0.0.1:19000", token="…")

def fetch(url: str) -> str:
    with mgr.lease(timeout=300) as inst:        # 阻塞直到拿到空闲实例
        with inst.session(human=True) as s:
            s.open(url)
            return s.content()

with ThreadPoolExecutor(max_workers=3) as ex:   # 3 个实例 → 3 个 worker
    results = list(ex.map(fetch, urls))
```

`mgr.lease()` 之所以线程安全，是因为 `mgr.pool` 是**懒创建的单例**——所有线程共享
同一份锁表。这是这个库最重要的一条不变量，`tests/test_lease_exclusivity.py` 用
20 线程抢 3 实例把它锁死。

#### 传任务参数

没有专门机制，就是普通的 Python 函数参数：

```python
def run(url: str, keyword: str) -> list[str]:
    with mgr.lease(where=lambda i: "us" in i.tags) as inst:
        with inst.session(human=True) as s:
            s.open(url)
            s.type("#q", keyword, clear=True)
            s.press("Enter")
            s.wait(Selector(".result"), timeout=20)
            return [e.text() for e in s.query_all(".result h3")]
```

#### 一个任务里开多个 tab

同一个实例上可以有多个 Session，但**不要并发操作它们**——`Session` 不是线程安全的，
`Transport` 会直接拒绝跨线程调用。

```python
with mgr.lease() as inst:
    a = inst.session(human=True)
    b = inst.session(human=True)
    try:
        a.open("https://example.com/1")     # 串行，不要放进两个线程
        b.open("https://example.com/2")
    finally:
        a.close()
        b.close()
```

handle 关闭时会强制关掉所有还开着的 Session 并记一条 warning。想让这种情况直接报错，
用 `Pool(providers, strict_close=True)`。

#### 多进程 / 多机

进程内的 `MemoryLease` 不跨进程。触发条件是**有几个进程**，不是有几个实例：

| 场景 | 后端 |
|---|---|
| 单进程串行 | 不用（或 `memory`，零成本） |
| 单进程多线程并发 | `memory`（默认） |
| 单进程跨 3 个 Manager 共 30 个实例 | `memory` |
| **多进程 / 多机共享同一批实例** | redis |
| 多进程但每进程静态绑死一个 uid | 不用（代价：崩溃后无法互相接管） |

### 5.6 拟人档位怎么选

#### 三层控制

```python
inst.session()                       # 默认 human=False，全部直通
inst.session(human=True)             # 默认全部拟人，用 DEFAULT 预设
inst.session(human=CAREFUL)          # 默认拟人且用 CAREFUL 预设

s.click(el)                          # 跟随 Session 默认
s.click(el, human=True)              # 单句开启
s.click(el, human=False)             # 单句关闭，抢时间
s.click(el, human=DEFAULT.replace(overshoot=0))   # 单句微调
```

规则：`None` → 继承 Session 默认；`False` → 直通；`True` → Session 默认预设
（未指定则 `DEFAULT`）；`HumanProfile` 实例 → 用它。

#### 三档预设

```python
from sleight import FAST, DEFAULT, CAREFUL
```

| | `FAST` | `DEFAULT` | `CAREFUL` |
|---|---|---|---|
| 用途 | 抢时间，低风险页面 | 日常 | 高风险页面：慢、抖、犹豫 |
| 弓形 `bow` | 0.10 | 0.18 | 0.26 |
| Fitts 斜率 `fitts_b` | 0.05 s/bit | 0.10 | 0.16 |
| overshoot 幅度 | 0.3 | 1.0 | 1.4 |
| 打字均值倍数 | 0.70 | 1.0 | 1.35 |
| 打字方差倍数 | 0.60 | 1.0 | 1.30 |
| 同一段 749 px 移动的点数 | 31 | 38 | 48 |

**点数是单调的**（FAST < DEFAULT < CAREFUL），这一点很重要：如果靠拉长 `step_delay`
来"变慢"，会得到一个反直觉的结果——谨慎模式发出的事件反而**更少**，轨迹更粗糙、
更容易被识别，而快速模式还更费带宽。快慢由 `fitts_b` 的时长控制。

#### 自定义

```python
from sleight import HumanProfile, DEFAULT

MY = DEFAULT.replace(
    fitts_b=0.13,              # 慢一点
    overshoot=0.0,             # 关掉冲过头
    think_every=(4, 9),        # 打字时更频繁地停顿思考
)

with inst.session(human=MY) as s:
    ...
```

主要字段：

| 字段 | 默认 | 含义 |
|---|---|---|
| `step_delay` | `(0.008, 0.020)` | 每个轨迹点后的停顿 = 鼠标**回报率**（50–125 Hz）。**不要用它调快慢** |
| `wind` | `3.0` | 手抖幅度。0 = 纯贝塞尔，没有抖动 |
| `bow` | `0.18` | 贝塞尔弓形，占路径长度的比例。0 = 直线 |
| `max_points` | `220` | 点数上限。跨屏拖拽不该发上千个事件 |
| `fitts_a` / `fitts_b` | `0.10` / `0.10` | Fitts 定律的截距（秒）与斜率（秒/bit） |
| `overshoot` | `1.0` | 冲过头的幅度系数。0 = 关闭 |
| `overshoot_threshold` | `500.0` | px。短距离不冲过头 |
| `overshoot_ramp` | `0.5` | 概率渐变区间，按阈值的倍数算。**不要设成 0** |
| `reaction` | `(0.060, 0.180)` | 到位后按下前的反应时间 |
| `dwell` | `(0.060, 0.150)` | 鼠标按压时长 |
| `inter_click` | `(0.040, 0.120)` | 双击的两下之间 |
| `key_dwell` | `(0.060, 0.120)` | 按键按下到抬起 |
| `typing_scale` / `typing_spread` | `1.0` / `1.0` | 击键间隔的均值 / 方差倍数 |
| `think_every` | `(8, 15)` | 平均每几个字符插一次思考停顿 |
| `think_pause` | `(0.20, 0.60)` | 思考停顿时长 |
| `landing_sigma` | `0.25` | 落点高斯的标准差，相对 box 半宽 |
| `edge_inset` | `3` | 落点内缩像素，会按元素尺寸自适应收窄 |
| `scroll_step` | `(80, 160)` | 单次 `mouseWheel` 的 deltaY |

#### 拟人到底做了什么

| 要素 | sleight | 反面教材 |
|---|---|---|
| 落点 | bbox 内截断高斯，自适应内缩 | 恒定点正中心 |
| 坐标 | 整数 | 用小数位当"抖动" |
| 轨迹 | 三阶贝塞尔，控制点单侧随机偏移，按弧长重参数化 | 直线插值 |
| 抖动 | WindMouse 风力项（相关噪声，lag-1 自相关 ≈ 0.72） | 无，或每点独立高斯（白噪声） |
| 速度 | 加速 → 巡航 → 减速 | 匀速 |
| 点数 | Fitts 定律，随距离/目标大小变 | 固定 `steps=N` |
| 步进间隔 | 8~20 ms，非固定 | 固定 sleep |
| overshoot | 超阈值后概率渐变触发，幅度随距离缩放 | 精确到达 / 每次都冲 |
| 前置停顿 | 到位后 60~180 ms 再按下 | 立刻按 |
| 按压时长 | 60~150 ms | 0 ms |
| 起点连续 | 维护当前鼠标位置 | 每次都从 (0,0) |
| 打字 | 逐字符 keyDown/keyUp，按 digraph 取间隔 | 一次 `insertText` |
| 双击 | 两次完整按下抬起，`detail` 依次 1、2 | `clickCount=2` 塞进单次 press |
| 滚动 | 多次小步 `mouseWheel` | 一次 `scrollTo` |

**关于中文输入的如实声明**：非 ASCII 走 `Input.insertText`，它**不产生**
`compositionstart` / `compositionupdate` / `compositionend`。真实 IME 输入会产生这三个
事件，认真做行为检测的站点能区分。说它"更接近真人中文输入"是过度声称——这是权衡之后
的选择（逐键 keydown 打中文更不真实），不是完美方案。

### 5.7 等待、超时与元素找不到

#### 六种等待条件

```python
from sleight import DomReady, Load, Text, Selector, Gone, NetworkIdle
```

| 条件 | 实现 | 什么时候用 |
|---|---|---|
| `DomReady()` | 订阅 `Page.lifecycleEvent` 的 `DOMContentLoaded` | 默认，够用 |
| `Load()` | 同上，等 `load` | 需要图片/子资源都到位 |
| `Text("Sign in")` | 轮询 `document.body.innerText` 包含子串 | 最直观，前端框架渲染完才出现的文案 |
| `Selector("#app")` | 轮询选择器命中数 > 0 | 等某个元素出现 |
| `Gone(".spinner")` | 轮询选择器命中数 == 0 | 等 loading 消失 |
| `NetworkIdle(quiet=0.5)` | 在飞请求集合为空后再静默 `quiet` 秒 | XHR 密集的页面 |

```python
s.open("https://example.com", wait=Text("Sign in"))
s.wait(Gone(".spinner"), timeout=20)
s.wait(NetworkIdle(quiet=1.0), timeout=30)
```

一次只收一个条件，要复合就连着调两次。

#### 三条语义上的坑

**① `NetworkIdle` 不等于"页面全部加载完"。** 它的语义是**「attach 之后发起的请求都
结束了」**——attach 之前已经在飞的请求 sleight 看不到。

长连接（WebSocket / EventSource）和分块流式响应（长轮询、SSE-over-fetch、gRPC-web）
永远不结束，会被主动排除；此外还有一条按年龄剔除的兜底（在飞超过 15 秒视为流）。

**② 同文档导航不产生任何 lifecycle 事件。** hash 路由（`#section`）的
`Page.navigate` 不返回 `loaderId`。sleight 检测到这种情况会让 `DomReady` / `Load`
直接返回，其余条件照常轮询。

**③ 超时异常带着最后一次求值结果。**

```python
from sleight.core.errors import TimeoutError

try:
    s.wait(Selector("#app"), timeout=10)
except TimeoutError as e:
    print(e)                 # timed out after 10s waiting for Selector('#app')
    print(e.last_value)      # 0 —— 最后一次数出来几个
```

#### 元素定位

```python
el = s.query("#login")             # 第一个，没命中返回 None
els = s.query_all("li.item")       # 全部，没命中返回空列表

el.box()                           # Box | None，viewport CSS 像素
el.require_box()                   # 拿不到就抛 ElementError
el.text()                          # innerText
el.attr("href")                    # 属性
el.in_viewport()                   # 现在能看见吗
el.hit_test(x, y)                  # 这个点最上层的是不是它
```

**作用域限制：只支持主 frame 的普通 DOM。** 不支持 iframe / OOPIF，不穿透 Shadow DOM。
需要这些用 Playwright。

#### 命中校验

每次 `click()` 都会做**两次**命中校验——取到几何时一次、轨迹跑完时一次。轨迹要跑
300 ms 到 2 s，这期间 cookie 横幅、懒加载的 sticky 头部、模态框都可能冒出来盖住目标。
只查一次等于没查。

被遮挡时抛的 `ElementError` 会点名挡住它的元素：

```
<Element '#submit'> is covered at (412, 680) after the pointer arrived;
topmost element is <div#cookie-banner.fixed.bottom-0>
```

多数库不做这步，症状是"点了但没反应"，排查极费时间。

#### `clear=True` 之前会检查焦点

点击只保证**几何命中**，不保证元素可聚焦——点一个 `<div>` 焦点会留在原处，于是
`Ctrl+A` + `Backspace` 清空的是**别的**输入框。`type(clear=True)` 会先确认
`document.activeElement` 真的落在目标上，不对就抛 `ElementError`。

### 5.8 多个 Manager 聚合成一个池

```python
from sleight import Pool
from sleight.providers import CloakBrowserManager, Plain

pool = Pool(
    [
        CloakBrowserManager("http://10.0.0.1:9000", token=T1, name="hk"),
        CloakBrowserManager("http://10.0.0.2:9000", token=T2, name="sg"),
        Plain("http://127.0.0.1:9222", name="local"),
    ],
    namespace="prod",          # 租约 key 前缀，隔离多套环境
    ttl=30.0,                  # 租约存活秒数
    discovery_ttl=5.0,         # list_instances() 的缓存秒数
)

with pool.lease() as inst:
    print(inst.info.uid)                       # "hk:5edcc28a-…"

with pool.lease(where=lambda i: "us" in i.tags) as inst:
    ...

with pool.lease(provider="sg") as inst:        # 只在新加坡那台上挑
    ...
```

Provider 的 `name` 在池内**必须唯一**，`Pool.__init__` 直接拒绝重复——uid 靠它保证
全局唯一。

#### Pool 的行为

| 问题 | 行为 |
|---|---|
| 发现开销 | `list_instances()` **并发**拉取 + TTL 缓存（默认 5 秒） |
| 慢 / 挂掉的 Manager | 单 provider 超时或抛异常 → 本轮跳过 + warning，**不阻塞全池**；连续失败进指数 backoff（上限 60 秒） |
| 选择策略 | first-free，但按 provider **打散起始下标**，否则总把第一个 Manager 塞满 |
| 未就绪的实例 | 默认参与调度，租到后 `ensure_ready()` 拉起；`ready_only=True` 可关 |
| 跨 Manager 迁移任务 | **不做**。租到哪个就在哪个跑完 |

**Pool 不做**负载权重、地域路由、健康评分。这些用 `where=` 表达，塞进 Pool 就会长成
调度器。

#### 不要自己做 round-robin

任务耗时不均是常态，轮询会把新任务硬塞给正忙的实例排队；`lease()` 的 first-free
天然是 work-stealing。「按 provider 打散」只作用于**平级空闲实例的起始顺序**，
不改变 first-free 语义。

## 7. 错误处理

```
SleightError
├── ConnectionError      端点不可达、隧道断
├── AuthError            401 / 403
├── ProtocolError        CDP 返回了 error，或消息不符合协议
├── InstanceError
│   ├── NotFound         instance_id 不存在（只由 status() 判定）
│   ├── NotReady         实例未启动
│   ├── Busy             租约被占
│   └── Crashed          实例 running 但 CDP 不通
├── SessionLost          连接已恢复，但会话状态丢失
├── LeaseLost            续租失败，本 handle 已失效
├── LeaseStillHeld       释放租约时仍有活动 Session（严格模式）
├── TimeoutError         等待条件超时，带 last_value
└── ElementError         选择器没命中 / 不可交互 / 被遮挡
```

```python
from sleight import errors               # errors.NotFound / errors.Busy / …
from sleight.core.errors import NotFound, Busy, ElementError
```

> 注意是 `sleight.core.errors`，不是 `sleight.errors` —— 后者只是顶层包里的一个属性
> 别名，`from sleight.errors import X` 会 `ModuleNotFoundError`。

> `sleight.errors.ConnectionError` 和 `TimeoutError` **有意遮蔽**内建同名异常，
> 给包内一个统一入口。`except Exception` 照样能接住，因为它们都继承 `Exception`。

### 只重试幂等操作

| 操作类别 | 例 | 断连后 |
|---|---|---|
| **幂等** | `list_instances` / `status` / `attach` / 只读 `eval` | 可以自动重试 |
| **非幂等** | `click` / `type` / `press` / `open` / 表单提交 | **绝不自动重放** |

sleight 不知道哪个 `click` 是安全的——重放可能意味着付了两次款、发了两条消息、
提交了两次表单。`recover()` 只负责把实例和连接恢复到可用状态，业务上从哪个检查点
继续由你决定。

### 隧道抖动 ≠ 浏览器崩溃

```
CDP 无响应
  ├─ Manager 也连不上          → ConnectionError（什么都别重启，是网络问题）
  ├─ status() = NOT_FOUND      → NotFound
  ├─ status() = STOPPED        → NotReady   → ensure_ready() 拉起
  └─ status() = RUNNING 但 CDP 不通 → Crashed → recover()
```

`recover()` 会 stop → launch → 等就绪。这是运维级操作，会丢掉浏览器里的所有 tab
（但不丢 `user_data_dir` 里的登录态）。

```python
from sleight.core.types import InstanceStatus

try:
    with mgr.lease(instance_id=pid) as inst:
        with inst.session() as s:
            s.open(url)
except errors.ConnectionError:
    if mgr.status(pid) is InstanceStatus.RUNNING:
        mgr.recover(pid)          # 浏览器僵了
    # 否则是网络问题，等一会儿重试
```

## 8. 排错手册

| 症状 | 原因 | 怎么办 |
|---|---|---|
| WS 握手 403 | Manager 的 WS 升级也要 `Authorization` 头，凭据塞不进 URL | 确认 `token` 传对了；`CloakBrowserManager` 会自动带 |
| `AuthError: 401 from …` | token 不对或过期 | 检查 `SLEIGHT_CLOAK_TOKEN` |
| `NotFound: no instance 'xxx' in this pool` | id 打错，或那个 profile 已被删 | `mgr.list_instances()` 看一眼 |
| `lease()` 一直不返回 | 实例全被占，默认阻塞等 | 加 `timeout=` 或 `block=False` |
| `NotReady: nothing answering at …/json/version` | `Plain` 起不了浏览器 | 自己把 Chrome 拉起来 |
| `InstanceError: instance … not ready after 60s` | Manager 起 profile 超时 | 看 Manager 日志；`/dev/shm` 满了是常见原因 |
| 点击"没反应" | 目标被遮挡 | 看 `ElementError` 消息里点名的那个元素，先关掉 cookie 横幅 |
| `ElementError: … does not have focus` | 点了个不可聚焦的元素就 `clear=True` | 换一个真正的 `<input>` 选择器 |
| `ElementError: … will not scroll into view` | 元素在嵌套滚动容器里，或横向出界 | 试 `human=False` 走 `DOM.scrollIntoViewIfNeeded` |
| `wait()` 一路超时 | 条件写错，或页面确实没加载 | 看异常的 `last_value`；先用 `s.text()[:200]` 确认页面内容 |
| `NetworkIdle` 永远不满足 | 页面有长轮询 | 换 `Selector()` / `Text()` 条件 |
| `RuntimeError: Transport is not thread-safe` | 跨线程共用 Session | 每个线程 `lease()` 自己的实例 |
| `LeaseLost` | 续租失败，连接已被掐断 | **不要重试这次操作**，重新 `lease()` |
| 坐标点偏了 133 px | 用了 `screen_height` 而不是 viewport 高度 | 用 `s.viewport()` 或 `spec.viewport_height` |

### A.5 开发机访问（SSH 隧道）

B 的宿主机端口只监听 `127.0.0.1:9000`。A 先连 OpenVPN，再用一条 SSH 隧道同时承载
Web UI、REST API、CDP WebSocket 和 noVNC。

Windows 批处理：

```bat
@echo off
title CloakBrowser Manager SSH Tunnel

set "HOST=manager.example.com"
set "USER=deploy"
set "SSH_PORT=22"
set "KEY=%USERPROFILE%\.ssh\id_ed25519"

set "LOCAL_PORT=19000"
set "REMOTE_PORT=9000"

echo Starting SSH tunnel...
echo Local URL: http://127.0.0.1:%LOCAL_PORT%

start "" cmd /c "timeout /t 3 /nobreak >nul && start http://127.0.0.1:%LOCAL_PORT%"

ssh ^
  -i "%KEY%" ^
  -N ^
  -T ^
  -p %SSH_PORT% ^
  -o ExitOnForwardFailure=yes ^
  -o ServerAliveInterval=30 ^
  -o ServerAliveCountMax=3 ^
  -L 127.0.0.1:%LOCAL_PORT%:127.0.0.1:%REMOTE_PORT% ^
  %USER%@%HOST%

echo SSH tunnel closed.
pause
```

Linux / macOS 一行：

```bash

  -L 127.0.0.1:19000:127.0.0.1:9000 deploy@manager.example.com
```

### A.7 资源与监控

`shm_size: 5gb` 是**整个容器共享**的 `/dev/shm`，不是每个 Profile 5 GB：

```
Profile 1 ─┐
Profile 2 ─┼─ 共享 5GB /dev/shm
Profile 3 ─┘
```

官方 README 给的粗略下限是每个运行 Profile 约 512 MB RAM，但真实页面、标签数量、
视频、Canvas 和缓存会显著改变占用。三个 Profile 可用 8 GB RAM 起步，**建议 16 GB
作为更稳妥的生产基线**，最终容量按峰值压测定。

```bash
curl --fail http://127.0.0.1:9000/api/status
docker compose ps
docker inspect --format '{{if .State.Health}}{{.State.Health.Status}}{{else}}no-healthcheck{{end}}' cloakbrowser-manager
docker exec cloakbrowser-manager df -h /dev/shm
docker stats --no-stream cloakbrowser-manager
```

重点监控：`/dev/shm` 使用率、容器 RSS、CPU 峰值、宿主机剩余内存、Manager 健康状态、
运行 Profile 数、启动失败次数、CDP 断开次数、任务 P95/P99、超时率、`/data` 磁盘容量。

- [ ] Manager、Profile、CDP、任务与资源指标已纳入监控

### A.11 扩容路线

| 活跃 Profile | 推荐形态 | 重点 |
|---|---|---|
| 3 | 1 台 B、1 个 Manager、3 个 Profile | 5 GB shm |
| 约 5 | 1 台 B、1 个 Manager、5 个 Profile | 建议 16 GB RAM，按压测调 shm |
| 约 10 | 2 个 Manager 或 2 台 B，各约 5 个 Profile | 独立端口、独立 `/data`，缩小故障域 |
| 几十个 | Pool 管理多台 B | 业务代码不直接选 Manager URL |
| 约 100 | 中央队列 + 每台 B 本地 Worker Agent | CDP 操作留在 B，只回传结构化结果 |

到较大规模时，每台 B 建议跑一个本地 Worker Agent，与本机 Manager 和 4~8 个 Profile
通信。这能减少跨机器 CDP WebSocket、避免任务节点成为网络瓶颈，并把网络波动限制在
单个浏览器节点内。

当前规模**不需要 Kubernetes**，也不需要为每个 Profile 映射独立端口。优先把版本固定、
网络边界、任务租约、备份回滚和真实压测做扎实。

sleight 已经把这些封装好了，这里列出来是为了排错时能直接 curl。

```
GET    /api/status                             {running_count, binary_version, profiles_total}
GET    /api/profiles                           实例列表（含状态）

GET    /api/profiles/{id}                      详情

DELETE /api/profiles/{id}                      删除
POST   /api/profiles/{id}/launch               启动
POST   /api/profiles/{id}/stop                 停止
GET    /api/profiles/{id}/status               {status, vnc_ws_port, display, cdp_url}
GET    /api/profiles/{id}/cdp                  CDP 入口（Upgrade 则升级为 WS）
GET    /api/profiles/{id}/cdp/json/version     标准 CDP HTTP 端点
GET    /api/profiles/{id}/cdp/json[/list]      target 列表
```

```bash
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:19000/api/status
```

### CDP 地址与鉴权

**所有实例共用 Manager 的同一个端口**，靠 URL path 区分——不是每实例一个端口。
多实例只需要一条隧道。

```
ws://HOST/api/profiles/{id}/cdp                            浏览器级 WS
http://HOST/api/profiles/{id}/cdp/json/version             版本
```

| 请求 | 无 token | 有 Bearer |
|---|---|---|
| `GET /api/profiles` | 401 | 200 |
| `GET …/cdp/json/list` | 401 | 200 |
| **WS Upgrade `…/cdp`** | **403** | **101** |

> ⚠️ **不要用 `/json/version` 返回的 `webSocketDebuggerUrl`。** Manager 把它重写成
> `ws://127.0.0.1:19000/...`——host 是**写死的**，换隧道端口或内网直连就错。
> sleight 用 `base_url` 自己拼，不碰这个字段。

### 幂等语义（实测）

| 操作 | 前置状态 | 状态码 | body |
|---|---|---|---|
| `POST launch` | stopped | 200 | `{profile_id, status:"running", …}` |
| `POST launch` | **running** | **409** | `{"detail":"Profile is already running"}` |
| `POST launch` | id 不存在 | 404 | `{"detail":"Profile not found"}` |
| `POST stop` | running | 200 | `{"ok":true}` |
| `POST stop` | **stopped** | **404** | `{"detail":"Profile is not running"}` |
| `POST stop` | **id 不存在** | **404** | `{"detail":"Profile is not running"}` ← 同上！ |
| `GET status` | id 不存在 | 404 | `{"detail":"Profile not found"}` |
| `GET …/cdp/json/version` | stopped | 404 | `{"detail":"Profile not running"}` |

三个结论，也是 sleight 内部实现的依据：

1. **`stop` 的 404 分不清「已停止」和「id 不存在」**，detail 完全相同。判定存在性
   只能用 `GET status`。sleight 的 `stop()` 因此会在 404 之后回头查一次 `status()`，
   而不是把打错的 id 静默当成幂等成功。
2. **停止的实例访问 CDP 返回 404，不是 401/502**，映射到 `NotReady` 而非 `Crashed`。
3. `POST /api/profiles` 传 `auto_launch: false` 可建一个不自动启动的 profile，
   适合做探测，不打扰正在跑的实例。

### 其它可观察量

| 字段 | 说明 |
|---|---|
| `cdp_url` | **相对路径** `/api/profiles/{id}/cdp` |
| `vnc_ws_port` / `display` | 分配规律：`6100+N` / `:100+N` |
| `screen_width` / `screen_height` | 坐标基准（1920×1080 → viewport 1920×947） |
| `tags` | `[{tag, color}]`，sleight 只取 `tag` 列 |

`/openapi.json` 可以取，但 **`securitySchemes` 是空的**——spec 没声明鉴权而实际强制，
不能直接拿它生成客户端。
