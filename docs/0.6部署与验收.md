# Sleight 0.6 统一服务部署与回滚

## 部署拓扑

Windows 运行 fin，Linux 运行 pyp、Sleight Python 服务和 Cloak Manager Docker。
fin 的浏览器请求只到 Sleight；Manager 地址、口令、插件与代理模板在 Sleight 配置。
默认 SQLite，可选 PostgreSQL；两者共用 hosts/deployments/events/ledger/objects 模型。
身份、模板、会话、配额、租约与审计使用统一事务存储；不再安装或运行 Redis。

Vue 页面由 GitHub 的 Node 构建，wheel/sdist 包含编译文件。用户部署只需 Python。
本轮包尚未发布 PyPI，先使用交付的 `sleight-0.6.0-py3-none-any.whl`。

## Linux 首次启动

```bash
python -m pip install ./sleight-0.6.0-py3-none-any.whl
export SLEIGHT_HOME=/var/lib/sleight
sleight ui --bind <Linux内网IP> --port 8700
```

首次启动显示一次管理员 token，保存后用它登录。再次启动不会重新生成。
也可使用 `SLEIGHT_UI_TOKEN` 作为管理员引导凭据。对外入口使用受控内网或 HTTPS。
`sleight ui` 自动读取启动目录下的 `.env`，系统环境变量优先；参考根目录 `.env.example`。
固定登录 token 使用 `SLEIGHT_UI_TOKEN=<已保存的 token>`，文件名必须为 `.env`。
运行用户需要 Docker/Compose 权限；推荐 systemd 常驻，回收器每 15 秒重试。

Web「部署环境」分为 fingerprint-chromium 和 Cloak Manager 两个区域。
Manager 按检测 Docker、选择版本与资源、检查部署三步操作；目录与容器名自动生成。
可导入现有 Compose；动态版本来自官方 Docker Hub，离线用缓存或手填，不自动升级。
新部署默认使用已验证的官方正式版 `cloakhq/cloakbrowser-manager:v0.1.6`，建议固定 digest：
`sha256:6c8f1c6bf53bb82f09f7d8b9cde30fb8b80a10fc32d15889ff2a1c7143156f01`。保留 CPU、内存、PID 和 shm 限制。
现有环境仍需备份后显式升级；新默认不会自动替换已有容器。最新真实运行验收见 [本地测试报告](统一服务本地测试报告.md)。
默认 4GB/CPU 2/PID 512/shm 1GB/并发 3 是起点；小内存机器应降低并发并给 pyp 留余量。
Windows Docker Desktop 可以使用命名卷，Linux 可用独立 bind mount。
导入旧环境后先备份完整数据，再通过 Web 升级；不能让旧客户端继续绕过服务启动实例。

## 用户、插件与代理

1. 在「插件与代理」推送解压后的 MV3 插件目录。源目录位于 Sleight 控制台机器。
2. Manager 模板填写容器内路径 `/data/extensions/<目录>`；原生模板填写执行主机的插件路径。
3. 保存代理模板，支持 `{sid}`，每个 fin 实例替换为独立会话号。代理密码加密存储。
4. 在「用户与运行 → 用户与权限」创建 fin 执行用户，设置默认环境、模板和并发上限。
   默认环境自动授权；额外环境和固定实例名称在同一表单设置，fin 兜底使用这些固定实例。
5. 为 fin 用户签发仅有 `execute` 的 token；明文只显示一次。
6. 为 pyp 创建管理员接入用户，签发仅有 `delegate` 的 token。

本机 Chrome / Edge 可以直接使用。fingerprint-chromium 可在 Web 安装；其他 Chromium
使用已安装可执行文件。普通 Chrome 137 起限制自动加载插件，可在有界面实例中手动安装。
Chrome for Testing 不提供专用下载入口，已有内核仍可使用且支持自动加载插件。
带认证的代理建议走 Cloak Manager；原生 Chromium 需使用无认证本机转发代理。
实例预览支持截图、网址和多标签页；远端实例还可打开 Manager 官方监控。
三份默认 Cloak 模板 Win-US-00/01/02 不含代理；临时实例默认随机种子。
新版 Manager 仅支持 GPU 家族，旧 AMD 模板映射 auto，无法精确保留旧 renderer 型号。
Manager 0.1.x 实例使用有界面浏览器，由容器的显示服务渲染，不支持按实例设置 headless=True。
控制台会读取实际 Manager 能力，隐藏不支持的无头选项；原生和旧 Manager 的选项按各自能力显示。

实例卡片提供「编辑实例」：停止后可修改名称、备注、模板、代理/插件、指纹种子和支持的启动选项。
内核、环境、长期/临时类型固定。保存保留实例 ID 和登录数据，启动配置下次启动生效；仅改名称不会覆盖原配置。
不需要数据库迁移。恢复旧客户端不丢失实例，但新增编辑入口需新版服务和编译页面。

## fin 与 pyp

fin 配置库只新增 `sleight_upstream`、`sleight_token` 两个键，类型为 `str`。
地址指向 Sleight 服务（通常 8700）；token 使用上面的 fin 执行身份。
保留旧 `cloak_*` 供旧代码和回滚；新服务模式不读取旧插件路径、Manager 地址或代理绑定。
本地 `.env` 的 `SLEIGHT_UPSTREAM`、`SLEIGHT_TOKEN` 优先于数据库，不能修改共享线上 base 配置做本地测试。

```dotenv
# pyp .env
SLEIGHT_UPSTREAM=http://<Linux内网IP>:8700
SLEIGHT_TOKEN=<pyp专用delegate token>
SLEIGHT_COOKIE_TTL=900
```

pyp 验证管理员后换取对应实际用户的短期 Sleight token，凭据加密保存在专用 HttpOnly cookie。
HTTP/SSE/WS 使用实际用户身份；JWT 和长期接入口令不透传给浏览器。升级后重新打开导航。
导航 migration `06a1b2c3d4e5` 无需重复新增；尚未应用的环境按现有流程执行 Alembic。
pyp Docker 中 `127.0.0.1` 是容器本身，必须填写能访问宿主机的地址。

## 数据库与备份

未设置 `SLEIGHT_HOME` 时，默认数据目录为启动工作目录下的 `data/`，SQLite 为 `data/control.db`。
`.env.example` 明确设置 `SLEIGHT_HOME=./data`；相对路径按启动目录解析，每次从同一目录启动。
旧版 `~/.sleight` 不会自动搬迁；要继续使用旧数据，将 `SLEIGHT_HOME` 指定为原目录。
默认 SQLite 为 `$SLEIGHT_HOME/control.db`。Web 迁回 SQLite 时新建 control-*.db，保留原文件。旧 `sleight.db`、`runtime.db`、`jobs.db`
首次启动自动导入，原文件保留用于回滚。旧模板与执行端凭据转为加密数据库记录。
`secret.key` 是独立加密密钥，必须与数据库一起备份；丢失后无法解密代理和执行端口令。
Manager 的 Compose `.env` 仍是受控部署文件，需要单独备份完整部署目录和数据卷。

在「用户与运行 → 数据库」填写 PostgreSQL 信息，先测试连接，再确认迁移。
目标必须为独立空数据库或空 schema；有业务表/视图时拒绝迁移。
成功后旧进程暂停写入，下次启动使用加密的 `$SLEIGHT_HOME/storage.json`；环境变量 SLEIGHT_DATABASE_URL 优先。
失败时恢复原库可写状态。回滚先停进程，移走 storage.json 回默认 SQLite，或恢复 storage.previous.json 回之前的 Web 配置；同时保留 secret.key。
数据库迁移不会迁走 native 目录、Manager 容器和插件文件，它们仍保存在原执行主机。

「阈值告警」后台每 5 秒采样，可选主机或指定 Manager 容器。默认 CPU 85%、内存 80%、持续 60 秒，重复通知 900 秒。
Webhook 未填则不通知；通知失败采用退避重试，正常后发送恢复通知。测试使用假 sender，不会发送真实 Lark 消息。

```bash
# 在服务停止、会话回收完成后执行；目标文件不能已存在
sleight db export backup.json
# 在空 PostgreSQL/独立 SLEIGHT_HOME 下导入
export SLEIGHT_DATABASE_URL='postgresql://user:password@host/sleight'
sleight db import backup.json
```

导入后将原 `secret.key` 复制到目标 SLEIGHT_HOME，或配置相同 `SLEIGHT_SECRET_KEY`。
使用专用数据库或通过连接 options 指定专用 schema。禁止向 fin/pyp 的业务 schema 导入。
导出不支持迁移活跃会话；有运行会话、本机进程或后台任务时会拒绝导出。
SQLite 单机事务，PostgreSQL 行锁；租约过期仅安排清理，确认浏览器停止后才释放名额。
当前服务以一个 Python 进程、一个 worker 运行；PostgreSQL 不会自动提供多 worker 会话路由。
数据库不可用时拒绝新增，不降级到无限容量；恢复后回收器持续重试。

## API 与 MCP

```python
from sleight.client import ServiceClient
with ServiceClient("http://host:8700", token="<执行token>") as client:
    profile = client.create_profile(name="任务", fingerprint_seed=1234)
    with client.session(profile["id"], human=True) as session:
        session.open("https://example.com")
        print(session.title())
```

接口位于 `/api/v1`；创建支持 Idempotency-Key，动作不自动重放。
SDK 心跳每 20 秒，客户端离线后约 120 秒进入回收。失败状态保留并发占用。
远程页面对象在导航、刷新及前进/后退后失效，需重新查询或 parse；资源捕获结束即释放服务端 tracker。
fin 出口 IP 采样由 Sleight 创建临时 context，探测结束自动销毁，不切换采集页面。
HTTP MCP `/mcp` 使用官方 Streamable HTTP SDK。stdio `sleight-mcp` 配置
`SLEIGHT_UPSTREAM`、`SLEIGHT_TOKEN` 即连接服务；使用独立 MCP token 避免多个 AI 共用浏览器会话。
旧 `SLEIGHT_CDP_URL`/本机内核入口仍保留兼容，但不参与远端服务管理。

远程执行端同样使用专用管理员 `delegate` 接入 token，主控制台会换取实际用户身份。
Web 和委托会话生成的长期 API token 关联原始接入凭据，不随页面退出失效；撤销接入凭据或禁用用户会使其失效。

## 切换与回滚

停止旧 fin 浏览器任务 → 备份数据库/密钥/Manager 数据 → 升级 Sleight 和 Manager →
配置默认环境及用户 token → 更新 pyp、fin → 单任务小并发验收 → 恢复调度。

回滚先停止新任务并回收会话，再恢复匹配的 Sleight/fin wheel、锁文件和配置。
数据库恢复升级前备份，Manager 恢复旧镜像、Compose、env 和完整数据，不能只换镜像。
旧 `cloak_*` 值及旧 SQLite 文件保留；新旧 SDK/服务接口需配套升级。
本地 fixture 通过不等于 Reuters 外站成功率保证，上线后另做小样本验证。
